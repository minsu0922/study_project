# 기능 점검 (2026-09-07)

화면 20개와 API 전부를 훑고, **새 계정을 만들어 실제로 써 보면서** 무엇이 없고
무엇이 어긋나는지 조사했다. 코드를 읽어 짐작한 것은 적지 않았다 — 이 문서의 모든
항목에는 화면이나 API가 실제로 돌려준 값이 근거로 붙어 있다.

## 2. 순위 1 — "푼 문제"가 두 가지 뜻으로 쓰인다

### 무엇을 봤나

새 계정을 만들어 **오늘의 퀴즈에서 한 문제를 풀고 틀렸다.** 그 상태에서 화면들이
하는 말을 그대로 옮긴다.

| 화면 | 하는 말 |
| --- | --- |
| 오늘의 퀴즈 | "1 / 10 · 이어서 풀기 (9문제)" |
| 오답노트 | 1건 |
| 문제 목록 (목록 부분) | ✗ Spring MVC 요청 처리 순서 — **틀림 표시** |
| 문제 목록 (통계 부분) | 푼 문제 **0** |
| 내 기록 | 푼 문제 **0** / 98 · 이번 주 **0** |
| 홈 | **"첫 문제를 풀어볼까요"** |

API로 대조한 값도 같다.

```
데일리.progress = { total: 10, solved: 1 }     ← 한 문제 풀었다
오답노트.totalElements = 1                      ← 그 문제를 틀렸다
요약.stats.solvedTotal = 0                      ← 맞힌 게 없다
```

### 원인

`StudySummaryResponse`의 주석이 정확히 적고 있다 — `solvedTotal`은
**"맞힌 적 있는 문제 수"** 다. 그런데 화면은 그 값을 "푼 문제"라는 이름으로 쓴다.

홈의 분기도 그 값을 본다.

```js
if (summary && summary.stats.solvedTotal === 0) {
  → "첫 문제를 풀어볼까요"
}
```

**틀린 것은 안 푼 것이 된다.** 그래서 첫 문제를 틀린 사람에게 앱 전체가 "너는 아직
아무것도 안 했다"고 말한다. 그리고 초보자일수록 첫 문제를 틀린다 — 이 문구가 가장
필요 없는 사람에게 정확히 그 문구가 간다.

문제 목록은 **한 화면 안에서 모순된다.** 위쪽 통계는 "푼 문제 0"인데 아래 목록의
같은 문제에는 ✗가 붙어 있다.

### 왜 이렇게 됐나

이 앱의 학습 모형에서는 "맞힌 것"이 맞는 단위인 자리가 실제로 있다. 분야별 진도
(31 / 40)는 맞힌 수라야 뜻이 통한다 — 틀린 것을 진도로 치면 게이지가 거짓말을 한다.
그 판단이 맞았고, 그 값을 만들었다. **그 뒤에 "푼 문제"라는 이름을 붙인 것이 사고다.**
값은 하나인데 이름이 둘의 뜻을 감당하고 있다.

### 고치는 방향

두 값을 나눠 두는 것이 근본이다 — `attemptedTotal`(제출한 문제 수)과
`solvedTotal`(맞힌 문제 수). 그러면 각 화면이 자기에게 맞는 것을 고른다.

- 분야별 진도 → 맞힌 수 (지금 그대로)
- "푼 문제" 카드 → 제출 수, 또는 "12문제 중 8개 정답"처럼 둘 다
- 홈의 첫 화면 분기 → **제출이 하나라도 있나**로

서버는 `Submission`에 이미 다 있다. 새 테이블도 배치도 필요 없고, 쿼리 하나와
필드 하나다.

### 고쳤다 (2026-09-08)

정확히 그렇게 했다 — `countAttemptedProblems` 쿼리 하나와 `attemptedTotal` 필드 하나.
기존 `countSolvedProblems`와 **`correct = true` 한 줄만 다르다.**

같은 상황(한 문제를 풀고 틀림)을 다시 만들어 재현했다.

| 화면 | 전 | 후 |
| --- | --- | --- |
| 홈 | "첫 문제를 풀어볼까요" | "오늘의 퀴즈 10문제 남았어요" + 통계 표시 |
| 내 기록 | 푼 문제 **0** / 98 | 푼 문제 **1** / 98 |
| 문제 목록 | 푼 문제 **0** (목록엔 ✗) | 푼 문제 **1** |
| 분야별 진도 | 0 / 35 | 0 / 35 (그대로 — 맞힌 게 없으니 정확하다) |

**진도를 안 건드린 것이 요점이다.** 두 값이 다른 질문에 답하게 됐으므로 한 화면에
나란히 있어도 어긋나지 않는다 — "푼 문제 1"과 "네트워크 0 / 35"는 둘 다 참이다.

통합 테스트 셋을 먼저 쓰고(빨간불 확인) 고쳤다. 틀린 제출이 푼 문제로 세지는지,
같은 문제를 세 번 풀어도 문제 수로 세는지, 새 계정은 둘 다 0인지.

## 3. 순위 2 — 검색이 없다

문제 목록이 받는 것은 도메인·난이도·상태·복습대기뿐이고, 문서 목록은 도메인뿐이다.
**키워드로 찾는 길이 어디에도 없다.**

지금은 문제 98개·문서 10편이라 필터로 견딘다. 그런데 이 프로젝트는 배치가 **매일
문제를 만들어 쌓는** 구조다. 200~300개가 되면 "그 TIME_WAIT 문제 다시 보고 싶다"를
할 방법이 없어진다. 오답노트와 복습 목록도 마찬가지다.

**가장 싼 것부터 하면 좋다.** 문서 API는 이미 `tag` 필터를 지원하는데
**화면에 그 입구가 없다.** 문서 카드에 태그 배지가 보이지만 누를 수 없는 글씨다.
배지를 링크로 만드는 것은 서버 변경이 0이고, 그것만으로 "이 태그의 문서 모아 보기"가
생긴다.

키워드 검색은 그다음이다. 문제는 지문이 길어 `LIKE`로도 쓸 만하고, 인덱스 실험
(docs/08)에서 이미 겪었듯 데이터가 커지면 그때 전문 검색을 얹으면 된다.

## 4. 순위 3 — 계정을 되찾을 방법이 없다

없는 것을 그대로 적는다.

| 없는 것 | 결과 |
| --- | --- |
| 비밀번호 변경 | 한 번 정한 비밀번호를 바꿀 수 없다 |
| 비밀번호 재설정 | 이메일을 안 받으므로 **구조적으로 불가능** |
| 회원 탈퇴 | 내 손으로 지울 수 없다 |

가입 화면에 확인 칸을 넣어(2026-09-07) 오타로 잃는 일은 막았지만, **잊으면 끝**인
것은 그대로다.

이건 구글 로그인과 한 묶음으로 보는 것이 낫다. 소셜 로그인이 붙으면 그 자체가 복구
경로가 된다(구글 계정으로 다시 들어온다). 이메일 칸을 지금 급히 받는 것보다,
소셜 로그인을 붙일 때 함께 정하는 편이 값싸다.

## 5. 순위 4 — 개념 문서를 훑을 수 없다

문서 한 편이 **9,338자**다(재귀 호출 심화편 실측). 그런데 화면에는 목차가 없다.

문서는 이미 절(`##`) 구조를 갖고 있다 — 검수 화면이 "절 12개"라고 세어 보여 줄
정도로 구조가 뚜렷하다. 그 구조가 **읽는 화면에서만 안 쓰인다.** 마크다운 제목에서
목차를 만드는 것은 화면 쪽 일이고 서버는 안 건드린다.

읽다가 자리를 잃으면 처음부터 스크롤해야 한다. "틀린 자리에서 바로 읽는다"가 이
문서들의 존재 이유인데, 그때 필요한 것은 통독이 아니라 **해당 절로 바로 가기**다.

## 6. 순위 5 — 학습 고리가 한쪽으로만 돈다

문제를 틀리면 채점 결과에 "📖 이 문제의 개념 문서 읽기"가 붙는다. 잘 동작한다.

반대가 없다. 문서를 다 읽고 나서 **"이 개념으로 문제 풀기"로 가는 길이 없다.**
읽은 사람이 할 수 있는 다음 행동은 메뉴로 돌아가 문제 목록에서 도메인을 다시 고르는
것뿐이다.

문서에는 이미 `domain`이 있고 문제 목록은 도메인 필터를 받는다. 링크 한 줄로
"이 분야 문제 풀기"까지는 지금 당장 된다. 더 정확히 하려면 문제 쪽의 근거 문서
(`documentSlug`)를 거꾸로 타면 "이 문서로 만든 문제들"이 된다.

## 8. 안 고쳐도 되는 것 — 확인만 하고 넘긴 것

조사하면서 "문제일까?" 하고 열어 봤다가 **설계대로였던** 것들이다. 다음 사람이 같은
곳을 다시 파지 않도록 적어 둔다.

| 의심한 것 | 실제 |
| --- | --- |
| 데일리 퀴즈를 중단하면 잃나 | 아니다. "이어서 풀기 (9문제)"로 정확히 남은 수를 알려 준다 |
| 복습이 안 잡히나 | 아니다. 복습은 **다음 날 아침부터** 열리는 설계고 화면에 그렇게 적혀 있다 |
| 순서 배열·짝짓기가 동작하나 | 한다. 누른 차례가 번호로 붙고 다 고르기 전에는 제출이 잠긴다 |
| 스트릭이 없는 것 | 뺀 것이 결정이다([12](12-daily-quiz.md)) — 하루 빠졌다고 벌을 주지 않는다 |

마지막 항목만 한마디 덧붙인다. 스트릭을 뺀 판단은 지금도 맞다고 본다. 다만 **대신
둘 것도 아직 없다** — 오늘 몫을 끝냈을 때 남는 것이 "내일 아침에 새 문제가 준비돼요"
한 줄뿐이다. 벌주지 않으면서 돌아올 이유를 만드는 장치는 따로 생각할 거리다.
