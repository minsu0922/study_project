# 18. 문제 목록 화면

작업 대상은 **문제 목록 화면 하나**다. 지도 화면과 문제 풀이 화면은 이 문서 범위 밖.

참고한 것: LeetCode(목록 구조), solved.ac(난이도 배지), Exercism(톤·여백), roadmap.sh(도메인 진척).

이 화면의 유일한 목적은 **다음에 풀 문제 하나를 30초 안에 고르게 하는 것**이다.
아래의 모든 결정은 그 문장으로 되돌아가 판정한다.

| 단계 | 내용 | 상태 |

## 2. 스펙을 코드에 대면서 드러난 것

레퍼런스를 보고 쓴 첫 스펙에는 **지금 DB로는 채울 수 없는 칸**이 있었다.
그중 두 개는 설계를 바꿔야 했다.

### 2.1 제목이 없었다 → 컬럼을 만들었다 (1단계에서 해결)

목록은 한 행에 제목 한 줄(14px)을 보여 준다. 그런데 `problem` 테이블에는 지문뿐이었다.

지문 앞부분을 잘라 쓰는 것이 첫 안이었는데, **바로 사흘 전에 그 길이 막혔다**.
2026-08-18에 중급·고급 지문을 "실무 장면"으로 쓰게 프롬프트를 고쳤기 때문이다
(`ClaudeProblemGenerator`의 `[상황 지문 쓰는 법]`). 그래서 지문 첫 문장이 이제 이렇다:

> 주문 API에서 처리 건수를 세려고 서비스 클래스에 static 카운터를 두고 요청마다 1씩 올린다…

무엇을 묻는 문제인지 알 수 없다. 한 개선이 다른 곳의 전제를 무너뜨린 자리다.

**결정**: `title` 컬럼을 만들고, **지문을 쓴 모델이 그 자리에서** 이름을 붙이게 한다.
구조화 출력 스키마의 맨 뒤에 두어(필드 순서 = 생성 순서) 지문·보기·해설을 다 쓴 뒤에
자기가 만든 것을 보고 짓게 했다. 나중에 따로 부르면 지문만 보고 지어야 하는데,
주제를 가장 잘 아는 것은 보기와 해설까지 아는 쪽이다.

**딸려 온 규칙**: 제목은 **안 푼 문제의 목록에도** 뜬다. 그래서 "정답을 제목에 쓰지 마라"가
프롬프트에 필요하다 — 이 줄이 없으면 `[금지]`의 "지문이 답을 알려 주는 문제"가
화면 하나 건너에서 되살아난다.

### 2.2 정답률은 이 서비스에서 성립하지 않는다 (2단계에서 결정할 것)

첫 스펙에는 LeetCode처럼 정답률 열이 있었다. 그런데 이 서비스의 사용자는 사실상 한 명이다.
문제별 정답률은 **0% 아니면 100%**다. LeetCode의 acceptance rate는 표본이 수백만이라 성립한다.

**대안**: 그 열을 `마지막 시도일` 또는 `틀린 횟수`로 바꾼다. 둘 다 1인 도구에서 뜻이 있고,
"다음에 풀 문제 하나를 고른다"는 목적에 정답률보다 직접적이다.

### 2.3 진척 게이지가 뒷걸음질친다 (2단계에서 결정할 것)

`18/42` 같은 분수는 분모가 고정일 때만 진척으로 읽힌다. 이 서비스는 **매일 배치가 문제를
추가**하므로 어제 40%가 오늘 37%가 된다. 게이지가 내려가는 것은 사기를 깎는다.

**대안**: 분모를 총 문제 수로 두지 말고 푼 개수를 절대값으로 보여 주거나, 도메인별 목표치를 고정한다.

### 2.4 "미풀이 우선" 정렬과 페이지네이션이 부딪힌다 (2단계에서 결정할 것)

한 문제를 풀고 목록으로 돌아오면 그 행이 뒤로 밀려 목록 전체가 한 칸 당겨진다.
무한 스크롤을 뺀 이유(위치를 잃는다)와 같은 문제가 정렬 쪽에서 생긴다.

**대안**: 목록 진입 시 정렬 스냅샷을 쿼리 파라미터로 고정한다.

### 2.5 토큰 이름이 기존 스타일시트와 충돌한다 (3단계에서 처리)

| 토큰 | 지금(`style.css`) | 새 스펙 |
| --- | --- | --- |
| `--accent` | `#f59e0b` 주황 — **복습 강조** | `#2563eb` 파랑 |
| `--radius` | 14px | 8px |
| 그림자 | `--shadow`/`--shadow-lift` 사용 중 | 전면 금지 |

같은 이름을 덮으면 목록 화면 하나가 아니라 홈·퀴즈·오답노트가 **동시에** 변형된다.
접두사(`--pl-*`)로 격리하거나, 범위를 "전 페이지 개편"으로 올려야 한다.

### 2.6 스트릭 금지 규칙이 기존 화면과 충돌한다

스펙은 "스트릭을 넣지 않는다"(주 3회 페이스에서 끊기면 이탈 요인)고 했는데,
`index.html`은 이미 "🔥 연속 n일째 완료 중"을 노출한다. 한 앱에 두 철학이 공존한다.
목록에서만 빼면 정리가 아니라 불일치다 — 한쪽으로 정해야 한다.

### 2.7 도메인은 10개가 아니라 11개

`SOFTWARE_ENGINEERING`이 2026-08-20에 추가됐다. "기본 5개 + 더보기"는 그대로 유효하다.

## 3. 1단계에서 실제로 한 일

### 3.1 스키마 (V13)

```sql
ALTER TABLE problem                  ADD COLUMN title VARCHAR(120) NULL AFTER type;
ALTER TABLE generated_problem_draft  ADD COLUMN title VARCHAR(120) NULL AFTER type;
```

**NULL을 허용한다.** 컬럼이 생기기 전에 만들어진 문제에는 넣을 값이 없다. 마이그레이션에서
지문 앞부분으로 채워 두면 **가짜 제목이 진짜인 척** 들어앉아 백필 대상을 고를 수 없어진다.
`NULL`은 "아직 없다"를 정직하게 말하고, 백필은 그 조건으로 대상을 찾는다.

**세 개의 상한이 서로 다르고, 그건 의도다.**

| 자리 | 값 | 역할 |
| --- | --- | --- |
| DB 컬럼 | 120자 | 저장 실패라는 **사고**를 막는 선 |
| `ProblemItemRule.TITLE_MAX` | 40자 | **품질** 기준 — 넘으면 경고(차단 아님) |
| 백필의 자르기 | 120자 | 한 건 때문에 배치 전체가 롤백되는 것을 막는다 |

같게 맞추면 한 글자 넘겼다고 저장이 실패하거나, 지시대로 쓴 제목이 매번 경고를 단다.

### 3.2 프롬프트 `[제목]` 절

- 물음이 아니라 **명사구**. 40자 이내.
- 지문의 첫 문장을 옮겨 오지 마라 (2.1의 이유).
- **정답을 제목에 쓰지 마라** (2.1의 딸려 온 규칙).
- (X)/(O) 실물 대비를 붙였다 — 이 저장소에서 추상적 금지는 여러 번 무시됐고 실물 예시는 지켜졌다.

### 3.3 검증 (`ProblemItemRule`)

경고 셋: `제목 없음`, `제목이 김`, `제목이 물음표로 끝남`.
**전부 경고이고 차단이 아니다** — 제목은 검수자가 그 자리에서 고칠 수 있는 한 줄이라,
버리는 비용(요금까지 낸 문제를 통째로 잃는다)이 고치는 비용보다 훨씬 크다.

물음표 하나로 재는 것은 조잡해 보이지만, 이 저장소가 여러 번 확인한 것이 그것이다 —
**세어 볼 수 있는 기준만 실제로 지켜진다.** "명사구인가"는 기계가 판정할 수 없고 물음표는 할 수 있다.

### 3.4 기존 33건 백필

`POST /api/admin/problems/backfill-titles` (관리 화면 버튼).

**Flyway 마이그레이션이 아닌 이유**: 이 저장소는 스키마만 마이그레이션으로 넣는다
(2026-08-12에 콘텐츠 시드 V2·V2_1·V3를 걷어내며 정한 규칙). 제목은 콘텐츠다.

**일회용 스크립트가 아닌 이유**: 한 번 돌리고 지우면 다음에 제목 없는 문제가 생겼을 때
아무 장치도 없다. 그리고 생긴다 — 등록 폼의 제목 칸은 선택이고, 모델도 가끔 빈 값을 낸다.

**이 기능의 코드는 대부분 "모델을 믿지 않는 부분"이다.**

| 위험 | 막는 방법 |
| --- | --- |
| 한 건을 빠뜨려 **전부 한 칸씩 밀린다** | 스키마가 `problemId`를 함께 받고, 짝짓기를 그 값으로 한다 |
| 요청하지 않은 id에 제목이 붙는다 | 모르는 id는 버린다 |
| 사람이 지은 제목을 갈아 치운다 | `Problem.fillTitleIfAbsent` — 이미 있으면 안 덮는다 |
| 정답을 요약한 제목이 나온다 | 프롬프트에 **지문만** 싣는다(보기·해설을 안 준다) |
| 한 건이 길어 배치 전체가 롤백된다 | 컬럼 상한에서 자른다 |

밀림 사고가 가장 무섭다. **아무 오류도 나지 않고**, 33건을 사람이 하나씩 대조해야만 드러난다.

한 번에 40건까지만 처리하고 남은 수를 응답에 담는다. 서버가 알아서 반복하지 않는 이유는,
프롬프트가 잘못돼 이상한 제목이 나오고 있다면 33건을 다 망친 뒤에 아는 것보다
40건에서 멈추고 눈으로 확인하는 쪽이 낫기 때문이다.

## 4. 화면 스펙 (2·3단계에서 구현)

### 4.1 디자인 토큰

```css
:root {
  --surface-0: #f8fafc;   /* 페이지 배경 */
  --surface-1: #f1f5f9;   /* 통계 카드, 게이지 트랙 */
  --surface-2: #ffffff;   /* 목록 카드 */

  --text-primary:   #0f172a;
  --text-secondary: #475569;
  --text-muted:     #94a3b8;

  --border:        #e2e8f0;
  --border-strong: #cbd5e1;

  --accent:    #2563eb;   /* 진척 게이지, 선택 상태 — 2.5의 충돌 주의 */
  --accent-bg: #eff6ff;

  --lv1-bg: #ecfdf5; --lv1-fg: #047857; --lv1-solid: #10b981;  /* 초급 */
  --lv2-bg: #fffbeb; --lv2-fg: #b45309; --lv2-solid: #f59e0b;  /* 중급 */
  --lv3-bg: #fef2f2; --lv3-fg: #b91c1c; --lv3-solid: #ef4444;  /* 고급 */

  --radius:    8px;
  --radius-lg: 12px;
  --sidebar-w: 170px;
  --max-w:     980px;
}
```

평면. 그림자 없음. 테두리는 1px hairline. 포인트색 하나.
폰트는 Pretendard 한 종, 굵기는 400과 500만 (600·700 금지).

| 역할 | 크기 | 굵기 | 색 |
| --- | --- | --- | --- |
| 통계 숫자 | 22px | 500 | primary |
| 문제 제목 | 14px | 400 | primary |
| 메타(도메인·유형) | 12px | 400 | secondary |
| 표 헤더·필터 라벨 | 11px | 400 | muted |
| 배지 | 11px | 500 | 난이도 fg |

### 4.2 데스크톱 (≥1024px)

```
┌─────────────────────────────────────────────────────┐
│  [푼 문제 128] [정답률 64%] [이번 주 14] [복습 9]     │  통계 4열
├──────────────┬──────────────────────────────────────┤
│ 도메인        │ (전체) (안 푼) (틀린) (복습)          │  상태 필터
│  네트워크 ▓▓░ │──────────────────────────────────────│
│  운영체제 ▓░░ │ 상태 제목            유형 난이도       │  표 헤더
│  DB      ▓▓▓ │──────────────────────────────────────│
│  자료구조 ▓▓▓ │ ✓  TCP 3-way…     객관식 [초급]      │
│  시스템설계▓░░│ ✓  TIME_WAIT…     서술형 [중급]      │
│  + 6개 더    │ ○  혼잡 제어…      서술형 [고급]      │
│              │ ✗  HTTP/2 HOL…     OX   [중급]       │
│ 난이도        │ ○  DNS 재귀…       단답형 [초급]      │
│ [초][중][고]  │                                      │
└──────────────┴──────────────────────────────────────┘
```

- **통계 카드**: 4열 그리드, gap 12px, `--surface-1`, 테두리 없음, padding 12px 14px.
  항목은 푼 문제 / 정답률 / 이번 주 / 복습 대기. **스트릭은 넣지 않는다**(2.6 참고).
- **사이드바**: 너비 `--sidebar-w`, 우측 1px 구분선. 이름(13px) + `18/42`(11px muted) + 진척 바(3px).
  **기본 5개만 노출**, 나머지는 "+ n개 더 보기" — 11개를 다 펴면 사이드바가 본문보다 길어진다.
  난이도 필터는 하단에 배지 3개 토글(다중 선택).
- **상태 필터**: 표 바로 위 가로 배치, 칩(radius 20px, padding 4px 11px, 12px), 단일 선택.
  **사이드바가 아니라 표 위에 둔다** — 필터가 한쪽에 8종 쌓이면 목록이 아니라 설정 화면이 된다.
- **목록 행**: 높이 40px 내외(padding 9px 14px), 하단 1px 테두리(마지막 행 제외).
  상태 아이콘(18px) / 제목(flex, 말줄임) / 유형(56px) / 난이도(42px).
  아이콘은 정답 `circle-check`(lv1-solid) / 오답 `circle-x`(lv3-solid) / 미풀이 `circle`(muted).
  hover 시 `--surface-1`, 클릭하면 풀이 화면으로.

### 4.3 모바일 (<768px)

```
┌──────────────────────┐
│ [푼 문제] [정답률]    │  통계 2×2
│ [이번 주] [복습]      │
├──────────────────────┤
│ (네트워크▓▓░)(OS▓░░)→│  도메인 가로 스크롤
│ (전체)(안 푼)(틀린)→ │  상태 가로 스크롤
├──────────────────────┤
│ ▌TCP 3-way…       ✓ │  2줄 행
│ ▌초급 · 객관식        │
└──────────────────────┘
```

- 사이드바를 **가로 스크롤 칩 줄로 대체**한다. 접히는 드로어를 만들지 않는다 — 탭 한 번이 줄어든다.
- 도메인 칩 최소 너비 88px, 이름 아래 진척 바 3px.
- 행을 2줄로 접는다: 1줄 제목, 2줄 `난이도 · 유형`.
- 난이도는 배지 대신 **행 좌측 3px 세로 스트립**(`--lv{n}-solid`). 좁은 폭에서 배지는 제목을 밀어낸다.
  세로 스트립은 한쪽 테두리이므로 `border-radius: 0`.
- 상태 아이콘은 우측 끝 고정.

브레이크포인트: ≥1024px 사이드바 / 768~1023px 사이드바 유지 + 열 하나 제거 / <768px 위 레이아웃.

### 4.4 접근성

- 정답·오답을 **색으로만** 알리지 않는다. 아이콘 + 텍스트(`aria-label="정답"`).
- 난이도 세로 스트립도 색 단독이므로 2줄 메타에 "초급/중급/고급" 글자를 반드시 남긴다.
- 필터 칩은 `role="radio"` 또는 `aria-pressed`. 키보드 포커스 링을 지운 채로 두지 않는다.
- 최소 글자 11px, 터치 타깃 44px 이상.

## 5. 데이터 계약 (2단계)

```ts
type Difficulty = 'BEGINNER' | 'INTERMEDIATE' | 'ADVANCED';
type QuestionType = 'MULTIPLE_CHOICE' | 'OX' | 'SHORT_ANSWER' | 'ESSAY';
type SolveState = 'UNSOLVED' | 'CORRECT' | 'WRONG';

interface ProblemListItem {
  id: number;
  title: string;         // title이 NULL이면 서버가 지문 앞부분으로 채워 내린다
  domain: string;        // 11개 도메인 코드
  difficulty: Difficulty;
  type: QuestionType;
  state: SolveState;     // 로그인 사용자 기준. 비로그인은 전부 UNSOLVED
  reviewDue: boolean;
}

interface DomainProgress { domain: string; label: string; solved: number; total: number; }
interface StudyStats { solvedTotal: number; correctRate: number; solvedThisWeek: number; reviewDue: number; }
```

- `title`의 **빈 값 대체는 서버가 한다.** 화면마다 각자 대체하면 규칙이 갈라진다.
  단, 관리 화면은 예외로 `null`을 그대로 받는다 — 거기서는 "제목이 없다"가 **고쳐야 할 정보**이고,
  수정 폼에 가짜 값을 미리 채우면 저장 한 번에 그것이 진짜 제목으로 박힌다.
- 목록은 페이지네이션. 기본 20개. 무한 스크롤 아님(위치를 잃는다).
- 정렬 기본값: 미풀이 우선 → 도메인 → 난이도 오름차순 (2.4의 스냅샷 문제 주의).
