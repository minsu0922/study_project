# 24. 자바 코드 문제 트랙

개념 문서와 따로, 자바 코드를 읽고 푸는 문제를 주 1회 만든다.
정답의 근거는 문서가 아니라 실행 결과다. 배치가 모델이 쓴 코드를 실제로 컴파일하고 실행해서
표시된 정답과 맞는 문제만 검수함에 들인다.

---

## 1. 왜 따로 두나

개념 문제는 문서를 근거로 낸다. 코드 문제는 "이 코드를 돌리면 무엇이 나오나"가 근거라서
문서에 묶으면 맞지 않는다. 대기열의 언어·런타임 주제 4개로 시험해 보니 코드 문제가 잘 나오는
주제는 하나뿐이었다.

| 정한 것 | 내용 | 이유 |
|---|---|---|
| 관리 | 문서와 따로. 주제 대기열도 종류(개념/코드)로 나눈다 | 근거와 주기가 다르다 |
| 유형 | 다섯 가지(아래 표) | 모두 객관식 틀이라 채점·화면을 그대로 쓴다 |
| 주기 | 주 1회, 일요일 02:47(KST) | 주제 하나로 5문제(초급 2·중급 2·고급 1) |
| 분야 | 언어·런타임에 넣고 "코드" 배지로 구분 | 새 분야를 만들면 순환·통계가 따로 논다 |
| 실행 검증 탈락 | 버리고 Actions 요약에만 이유를 남긴다 | 정답이 틀린 문제는 고쳐 쓸 가치가 낮다 |
| 언어 | 자바만. 다만 `language` 칸은 둔다 | 나중에 SQL 등으로 넓힐 자리 |
| 주제 | 다 쓰면 처음부터 되풀이 | 되풀이할 때는 같은 주제의 앞선 코드를 프롬프트에 실어 겹침을 막는다 |
| 문장 | "~다"로 끝낸다 | 개념 문제와 말투를 맞춘다 |

## 2. 다섯 유형

| 유형 | 코드 | 보기 | 기계가 대조하는 값 |
|---|---|---|---|
| 실행 결과 `CODE_OUTPUT` | 완성된 코드 | 출력 | `expectedOutput` |
| 빈칸 코드 `CODE_BLANK` | `____` 한 곳이 빈 코드 | 빈칸에 넣을 코드 | 정답을 넣은 출력이 `expectedOutput` |
| 오류 지점 `CODE_ERROR` | 완성된 코드 | "N행에서 예외이름" | `targetLine`, `errorType` |
| 컴파일 여부 `CODE_COMPILE` | 완성된 코드 | "N행에서 컴파일 오류" | `targetLine`(0이면 컴파일됨) |
| 한 줄 고치기 `CODE_FIX` | 버그가 든 코드 | 그 줄을 대신할 코드 | 바꾼 출력이 `expectedOutput` |

모델에게 보기 문장만 받으면 실행 결과와 견줄 방법이 문장 해석뿐이다.
그래서 정답을 **기계가 대조할 값**으로도 따로 받는다(`CodeProblem.Item`).

## 3. 흐름

```
job 1  1. 생성      (API 키 있음)  주제를 고르고 Claude에게 후보를 받는다. 코드는 돌리지 않는다
       2. 실행 검증 (API 키 없음)  후보를 돌려 정답과 대조하고, 통과한 것만 generated/ 에 쓴다
                                  글과 실행 결과를 규칙으로 대조한다(0단계)
                                  보기마다 돌린 결과를 code-runs.json에 적는다
       → 결과 파일만 artifact로 넘긴다
job 2  3. AI 검수   (API 키 있음)  모르고 풀기(A) → 대조 검수(B). 지적을 파일에 덧붙인다
       4. 커밋      (git 토큰)     generated/ 를 main에 push
```

워크플로는 `.github/workflows/llm-code-problems.yml`, 진입점은 `CodeProblemCli --phase=generate|verify|review`다.

### 키와 토큰을 어디서 쓰나

모델이 쓴 코드를 돌린 러너는 믿지 않는다. 그 코드가 빌드 스크립트나 `.git/hooks`를 바꿔 두면,
다음에 키나 토큰을 쥐고 도는 `gradlew`·`git`이 그것을 실행한다. 그래서 job을 둘로 나눴다.

| 지키는 것 | 방법 |
|---|---|
| 실행 중 키 유출 | 검증 스텝에는 키가 없다. Gradle 태스크도 `generate`·`review`일 때만 키를 넘긴다 |
| 자식 프로세스 | 환경변수를 비우고 실행한다. 5초, `-Xmx64m` 상한 |
| 작업 공간 오염 | 검수·커밋은 새 러너(job 2)에서 한다. job 1에서는 정해진 파일만 받는다 |
| git 토큰 | `persist-credentials: false`, 토큰은 push 스텝에만 |
| 파일·네트워크 접근 | 실행 전에 금지 소재 규칙(`CodeProblemRule`)이 걸러 낸다 |

## 4. 실행 검증

`CodeRunner`가 임시 폴더에 `Main.java`를 쓰고 같은 JVM의 컴파일러로 컴파일한 뒤 다른 프로세스로 실행한다.
`CodeVerifier`가 유형마다 대조한다.

| 유형 | 버리는 경우 |
|---|---|
| 실행 결과 | 실제 출력이 예상과 다르거나, 정답 보기가 실제 출력과 다르다 |
| 빈칸·고치기 | 정답을 넣어도 예상 출력이 안 나온다. **오답을 넣었는데 같은 출력이 나온다**(정답이 둘) |
| 한 줄 고치기 | 고치기 전 코드가 이미 기대 출력을 낸다 |
| 오류 지점 | 예외 이름이나 줄이 다르다. 정답 보기에 예외 이름과 "N행"이 없다 |
| 컴파일 여부 | 오류 나는 줄이 다르다 |

빈칸·고치기는 같은 뜻의 코드가 여럿일 수 있는 유형이다. 오답을 하나씩 넣어 돌려 보지 않으면 낼 수 없다.

실행 전에 거르는 금지 소재는 돌릴 때마다 결과가 달라지거나 밖을 건드리는 것들이다.
스레드, 난수, 현재 시각, `HashMap`·`HashSet`, 입력, 파일, 네트워크, 환경 접근, 유니코드 이스케이프.

## 5. 검수

실행 검증은 정답이 맞는지만 보장한다. 해설, 오답 이유, 난이도, 문장은 검수가 본다.
지적은 모두 검수함에 달리고 **들여오기는 막지 않는다**. 막을지는 측정을 거쳐 정한다.

### 0단계 — 규칙 대조 (`CodeFactChecker`, 요금 없음)

| 검사 | 걸리는 예 | 종류(등급) |
|---|---|---|
| 코드에 없는 줄 번호 | 18줄 코드인데 해설에 "21행" | 해설 어긋남·질문 어긋남(결함) |
| 질문에 적힌 출력 | 고치기 질문은 "0을 출력합니다", 실제는 1 | 질문 어긋남(결함) |
| 오답 이유의 주장 | "2가 출력된다"·"컴파일되지 않는다"가 그 오답을 넣어 돌린 결과와 다르다 | 오답 이유 어긋남(결함) |
| 답을 알려 주는 주석 | `// 여기서 예외` | 주석이 답을 드러냄(다듬기) |

글에서 값을 뽑는 일은 규칙으로 하므로 숫자, 따옴표 친 글, `true`·`false`·`null`만 본다.
오답 이유의 앞 문장("~라고 오해했다")은 틀린 말이 맞으니 대조에서 뺀다.
10-13에 들어온 5문제에 돌렸을 때 지적은 0건이었다.

### A — 모르고 풀기

정답, 해설, 오답 이유, 실행 결과, 매긴 난이도를 가리고 보기를 섞어서 학습자처럼 풀게 한다.
지금까지 생성된 코드 문제는 정답이 모두 1번이라, 섞지 않으면 번호로 고를 수 있다.

| 결과 | 종류(등급) |
|---|---|
| 정답을 골랐다 | 풀이(의견) |
| 다른 보기를 골랐다 | AI가 다른 답을 고름(다듬기) |
| 두 가지로 읽힌다고 했다 | 질문이 모호함(다듬기) |
| 느낀 난이도가 두 단계 다르다 | 난이도 어긋남(다듬기) |

AI가 틀리게 골라도 결함으로 보지 않는다. 정답은 실행으로 확인했으니, 함정이 지나치거나 질문이 흐리다는 신호로 읽는다.
난이도는 한 단계 차이가 정의의 경계에서 흔히 갈려서 두 단계(초급↔고급)만 지적한다.

### B — 대조 검수

정답을 보여 주고 **실제 실행 결과도 함께 준다**. 빈칸·고치기는 보기 넷을 하나씩 넣어 돌린 결과까지 준다.
모델이 코드를 머릿속으로 돌리다 틀리면 맞는 해설을 틀렸다고 지적하게 된다. 결과를 주면 그 계산을 안 해도 된다.

| 종류 | 보는 것 | 등급 |
|---|---|---|
| 해설 어긋남 | 출력·예외·실행 순서, "N행"이 가리키는 줄 | 결함 |
| 오답 이유 어긋남 | 오해 문장 뒤의 결과가 실제와 다르다 | 결함 |
| 실행 환경 의존 | JVM 옵션·JDK 버전·인코딩에 따라 답이 바뀐다(예: Integer 캐시 상한 `-XX:AutoBoxCacheMax`) | 결함 |
| 주제 이탈 | 주제를 몰라도 풀리거나 다른 함정이 답을 가른다 | 다듬기 |
| 보기 단서 | 코드를 따라가지 않아도 모양만 보고 지워지는 오답 | 다듬기 |
| 어색한 문장, 가독성 | 기존 검수와 같다 | 의견 |

A를 B보다 먼저 부른다. 순서가 바뀌면 A가 답을 본 뒤가 된다. 한쪽이 실패해도 다른 쪽 지적은 낸다.

### 제안과 적용

| 지적 | 제안 | 적용하면 |
|---|---|---|
| 해설 어긋남 | 고친 해설 전체 | 해설만 바뀐다 |
| 오답 이유 어긋남 | 그 보기의 고친 이유. 오답마다 지적 하나 | 그 오답 설명만 바뀐다 |
| 어색한 문장 | 질문·해설·오답 이유에서 그 부분만 바꾼 글 | 그 칸만 바뀐다 |
| 코드, 정답, 보기 글 | 제안하지 않는다 | 바꾸면 실행 검증을 다시 해야 한다 |

검수함의 버튼이 `POST /api/admin/llm-problems/{id}/ai-findings/{index}/apply-suggestion`을 부른다.
적용한 지적에는 바꾸기 전 글이 한 줄로 남아 손으로 되돌릴 수 있다.

제안 대상(`FixTarget`)에 해설·오답 이유를 더하면서 개념 문제 검수가 모델에게 고르게 하는
대상은 `AfterSolveFix`로 떼어 냈다. 응답 스키마에 실리는 값이라 같이 늘리면 측정을 거친 요청이 바뀐다.

## 6. 파일과 DB

문제 파일은 개념 문제 파일과 같은 모양에 곁칸 둘을 더한다(`GeneratedBatchFile`).

| 칸 | 내용 |
|---|---|
| `codeTopic` | 이 파일을 낸 코드 주제. 되풀이할 때 앞선 코드를 찾는 열쇠 |
| `codeParts` | 문제마다 코드·유형·대조 값. `problems`와 번호(`problemIndex`)로 짝짓는다 |
| `reviewFindings` | 0단계·A·B 지적. 역시 번호로 짝짓는다 |

파일 이름은 `<날짜>-code-beg|int|adv.json`이다. 한 주제에서 난이도를 섞어 내므로 난이도별로 나눠 쓴다.

**코드 문제는 번호로 짝짓는다.** 개념 문제는 지적을 질문 문장으로 초안에 붙이는데,
코드 문제는 "다음 코드를 실행했을 때 출력되는 것은?"처럼 질문이 서로 같은 일이 흔하다.
문장으로 짝지으면 코드가 엉뚱한 문제에 붙어 정답이 틀린 문제가 된다. 그래서 들여올 때 한 건씩 저장한다.

| 마이그레이션 | 내용 |
|---|---|
| V39 | `problem.code`, `code_language` (초안도) |
| V40 | `topic_queue.kind` — CONCEPT/CODE |
| V41 | 초안 `code_kind`, `expected_output` |
| V42 | `problem.code_focus_line`, `code_choices`, 초안 `code_focus_line` |

주제 대기열은 한 표를 종류로 나누고, 내보내는 파일만 `_topics.json`과 `_code-topics.json`으로 나눈다.
한 파일에 섞으면 문서 배치가 주제를 고르는 자리마다 종류를 검사해야 하고, 하나만 빠져도
자바 문법 주제로 개념 문서가 생성된다.

## 7. 화면

| 자리 | 하는 일 |
|---|---|
| 코드 블록 | 줄 번호를 붙여 그린다(`codeBlockHtml`, `js/api.js`) |
| 강조할 줄 | 빈칸이 있는 줄, 고칠 줄에 띠를 친다. 오류 지점·컴파일 여부의 줄은 그 자체가 정답이라 강조하지 않는다 |
| 코드로 된 보기 | 고정폭으로 그리고, 네 보기에 공통인 앞뒤는 흐리게, 다른 부분은 진하게 그린다(`codeChoicesHtml`) |
| 보기 길이 | 생성 프롬프트에 코드 보기 45자 제한. 길면 긴 조건식을 앞줄 변수로 빼게 한다 |
| 검수함 | 코드·유형 배지·배치가 확인한 출력, 지적 요약 표에 코드 문제 종류 열 |

관리 화면의 문제 수정 폼에도 "강조할 줄"과 "보기가 코드다" 칸이 있다. 폼이 문제를 통째로
다시 보내서 칸이 없으면 수정할 때마다 값이 지워진다.

## 9. 운영

```powershell
# 로컬에서 한 번 돌리기 (generate·review는 요금이 든다)
$env:IN_TOPIC = "String 불변성과 StringBuilder"
.\gradlew.bat generateCodeProblems -PcodeArgs="--phase=generate --topic-env=IN_TOPIC"
.\gradlew.bat generateCodeProblems -PcodeArgs="--phase=verify"
.\gradlew.bat generateCodeProblems -PcodeArgs="--phase=review"
```

- 주제는 관리 콘솔 주제 대기열 화면의 "코드 문제 주제" 탭(`/admin/topics.html?kind=CODE`)에서 넣고, 앱이 쓴 `generated/_code-topics.json`을 커밋한다.
- 코드 문제 배치는 `llm.batch-enabled`를 보지 않는다. 멈추려면 코드 주제를 비우거나 워크플로를 끈다.
- Windows 콘솔에서는 CLI의 한글 요약이 깨져 보인다. Actions 요약에서는 정상이다.
