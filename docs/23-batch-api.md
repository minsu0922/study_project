# 23. 배치 생성을 Batch API로 돌리기

새벽 배치(GitHub Actions)가 부르는 Claude API를 Batch API로 옮겼다.
Batch API는 답이 늦는 대신 입력·출력·사고 토큰 요금이 모두 반값이다.
새벽 배치는 결과를 기다리는 사람이 없으니 늦어도 잃는 것이 없다.

---

## 1. 왜 이것부터 했나

비용을 줄이는 방법을 품질에 주는 영향 순으로 늘어놓고 영향이 없는 것부터 골랐다.

| 방법 | 줄어드는 폭 | 품질 영향 | 결정 |
|---|---|---|---|
| Batch API | 생성·검수 모두 50% | 없음. 같은 모델, 같은 요청 | **이번에 함** |
| 프롬프트 캐시 | 거의 없음 | 없음 | 안 함. 같은 문서를 다시 읽는 호출이 하루 간격이라 캐시 수명(최대 1시간)을 넘긴다. 한 실행 안의 호출은 지시문이 서로 달라 겹치는 앞부분이 없다 |
| 검수 사고 수준 낮추기 | 검수 출력 요금 일부 | 적발률이 떨어질 수 있음 | 나중. 측정 도구(`evalReview`)로 재고 정한다 |
| 생성 사고 수준 낮추기 | 생성 비용의 큰 덩어리일 수 있음 | 문서·문제 품질이 떨어질 수 있음 | 나중. 위험이 가장 크다 |
| 더 싼 모델 | - | 검수는 Sonnet 5가 더 나빴다(docs/22 §5) | 안 함 |

## 2. 구조

API를 부르는 곳을 `ClaudeCalls` 하나로 모았다. 생성기 4개와 검수기 2개가 모두 여기를 거친다.

| 모드 | 누가 켜나 | 동작 |
|---|---|---|
| 바로 호출 | 관리자 화면, 측정 도구, `DraftGeneratorCli --batch-api=false` | 지금까지와 같다 |
| 배치 호출 | `DraftGeneratorCli` (기본) | 제출 → 30초마다 상태 확인 → 결과 읽기 |

2026-10-10부터 `DraftGeneratorCli`는 옵션을 생략해도 배치 호출이다. 손으로 여러 칸을 채우면서
옵션을 빠뜨려 정가를 낸 날이 있었다. 바로 받아야 할 때만 `--batch-api=false`를 준다.
그날 잰 대기 시간은 생성 호출 하나에 17분이었다.

관리자 화면의 "문서로 문제 만들기"는 사람이 기다리는 작업이라 바로 호출에 둔다.

**호출 하나를 배치 하나로 보낸다.** 하루 작업은 생성 → 검사 → 검수가 앞 결과를 받아야
다음을 보낼 수 있는 사슬이다. 여러 호출을 한 배치로 묶으려면 이 흐름을 다시 짜야 한다.
할인율은 요청 수와 상관없이 같으니 묶어서 더 얻는 것은 없다.

**45분이 넘으면 정가로 바로 부른다.** 공식 설명은 "대부분 1시간 안, 최대 24시간"이다.
기다리다 못 받으면 그날 문서나 문제가 하루 밀리고 4일 주기 일정 전체가 흔들린다.
배치를 취소하고 바로 부르면 그 호출 하나만 정가를 낸다. 실패·만료된 요청도 같은 방식으로 대신한다.

**응답 JSON은 두 모드 모두 우리 코드가 읽는다.** SDK의 구조화 결과(`StructuredMessage`)는
생성자가 막혀 있어 배치 결과로는 만들 수 없다. 한쪽만 SDK가 읽으면 두 모드가 다르게 읽을 수 있다.
그래서 바로 호출도 원문 JSON을 받아 같은 방식으로 읽는다. 실제 생성 파일의 JSON으로
읽기 결과를 확인하는 테스트가 있다(`ClaudeCallsTest`).

**요청 본문은 통째로 옮긴다.** 배치 요청의 `params`는 메시지 요청 본문과 같은 JSON이다.
필드를 하나씩 옮기면 나중에 붙인 설정(도구, 사고 등)을 빠뜨리기 쉽다.

## 3. 확인한 것

| 확인 | 결과 |
|---|---|
| 구조화 출력을 배치에 넣을 수 있나 | 된다. 공식 문서가 배치에서 막는 것은 스트리밍, fast mode, `max_tokens: 0` 셋뿐이다. SDK 배치 요청에도 `outputConfig`가 있다 |
| 사고(thinking) | 공식 문서의 지원 목록에 있다 |
| Actions 실행 시간 | 저장소가 공개라 무료, 한도 없음. 실행 제한만 20분에서 300분으로 늘렸다 |
| 최악의 실행 시간 | 문서일 호출 4번(문서 2 + 사실 검수 2) × (45분 대기 + 정가 호출) ≈ 220분 |

## 4. 비용 기록

호출마다 토큰 수와 배치 여부를 기록하고 실행이 끝나면 이름별 표를 Actions 요약에 남긴다.

```
💰 2026-09-29 API 비용 약 $0.45 — 사고 토큰은 출력에 포함. 배치 호출은 반값으로 계산

| 호출 | 횟수 | 입력 토큰 | 출력 토큰 | 금액 |
| 문제 생성 | 1 (배치 1) | ... |
| 문제 검수 | 2 (배치 2) | ... |
```

"배치 n"이 횟수보다 작으면 그만큼 45분을 넘겨 정가로 부른 것이다.
금액은 측정 도구와 같은 단가표로 계산한 추정치다. 정확한 청구액은 Anthropic 콘솔에서 본다.

## 5. 남은 것

| 할 일 | 시기 |
|---|---|
| 첫 며칠의 배치 대기 시간을 보고 45분 기한 조정 | 적용 뒤 1주 |
| 생성 비용의 실제 크기를 보고 사고 수준 낮추기를 검토할지 정함 | 2주 점검(docs/22 §6) 때 |
| 같은 단계의 호출 묶기(사실 검수 입문·심화, 문제 검수 두 호출) | 대기 시간이 길게 나오면 |
