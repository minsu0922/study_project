# 27. 주제 로드맵과 작성 지시

2026-10-29~31에 만들었다. 주제 대기열을 분야별 학습 순서로 다시 쌓고, 줄마다 붙은 메모를 문서 생성 모델에게 작성 지시로 넘긴다.

## 1. 왜 만들었나

대기열의 한 줄은 원래 "Spring 트랜잭션" 같은 **범위**였다. 배치가 그 안에서 세부 주제를 골라 문서를 썼다.
그래서 같은 분야 문서가 쌓여도 순서가 없었다. 비전공자가 처음부터 따라 읽을 길이 없었다.

메모 칸은 있었지만 사람용 기록이었다. 대기열 id와 날짜가 섞여 있어 모델에 실을 수 없었다.
문서의 각도는 주제 문장 하나가 정했다.

## 2. 로드맵 블록

대기열 맨 위에 분야별 블록을 차례로 쌓았다. 한 줄이 문서 한 편이다. 아래 번호는 처음 쌓은 자리다.
주제를 쓰면 그 줄은 안 쓴 주제 뒤로 가므로 지금 차례와는 다를 수 있다.

| 자리 | 분야 | 편수 |
|---|---|---|
| 1~11 | 클라우드·인프라 | 11 |
| 12~24 | 네트워크 | 13 |
| 25~35 | 운영체제 | 11 |
| 36~44 | 데이터베이스 | 9 |
| 45~55 | 시스템설계 | 11 |
| 56~63 | 보안 | 8 |
| 64~72 | 언어·런타임 | 9 |
| 73~84 | 스프링·백엔드 | 12 |

자료구조·알고리즘은 건너뛰었다. 흐름에 맞는 문서가 이미 있으면 같은 편을 새로 만들지 않았다. 그 문서가 그 자리 몫을 한다.
주제 문장은 "개념 — 출발 장면" 꼴이다. 예: "포트 — 한 컴퓨터에서 카톡과 브라우저가 동시에 통신해도 서로 섞이지 않는 이유".

## 3. 작성 지시 형식

메모를 이름표 단 줄로 쓴다. 한 줄이 한 칸이고 줄바꿈이 칸을 나눈다.

```
핵심 개념: 포트, 소켓, 잘 알려진 포트
설명할 것: 질문 하나 / 질문 둘 / 질문 셋
다루지 않을 것: NAT (선택)
실물: 50만 건에서 1.8초가 16ms로 (선택)
그림: 한 컴퓨터 안에서 포트로 갈라지는 흐름 (flowchart) (선택)
```

| 칸 | 필수 | 입문편 | 심화편 | 모델에게 하는 말 |
|---|---|---|---|---|
| 핵심 개념 | ✓ | 실음 | 실음 | 본문에서 반드시 정의한다. 심화편은 한 단계 깊이 다룬다 |
| 설명할 것 | ✓ | 실음 | 안 실음 | 질문을 본문이 답하는 순서의 뼈대로 삼는다 |
| 다루지 않을 것 | | 실음 | 실음 | 이름만 꺼내고 깊게 들어가지 않는다 |
| 실물 | | 실음 | 실음 | 사실과 수치를 바꾸지 않고 그대로 쓴다 |
| 그림 | | 실음 | 안 실음 | 지정하면 입문편이 반드시 그린다. 끝 괄호는 mermaid 종류 |

**앞의 두 칸이 모두 있어야 지시로 본다.** 하나라도 없으면 옛 메모로 보고 싣지 않는다. 그 줄은 예전처럼 범위로 돈다.
배치 로그에 "작성 지시: 메모를 실었습니다" 또는 "작성 지시: 없음"이 찍혀 어느 쪽인지 알 수 있다.

지시가 실리면 주제를 범위로 보지 않고 **그대로 쓴다.** 로드맵 주제는 이미 한 편 크기다.
범위 안에서 다시 고르라고 하면 한 번 더 좁혀 엉뚱한 주제를 쓰고 기존 문서와 겹치지 말라는 규칙에 밀려 주제를 피해 간다.

### 심화편에 "설명할 것"을 싣지 않는 이유

심화편은 입문편을 읽은 사람이 보는 글이다. 같은 질문 목록을 주면 입문편과 같은 글이 한 번 더 나온다.
그림 지정을 싣지 않는 이유도 같다. 입문편이 그린 그림을 다시 그린다.

### 심화편의 "뒤 편이 다룰 주제"

질문 목록이 없는 심화편은 범위가 넓어진다. 2026-10-29 실물 생성에서 네트워크 심화편이 NAT·리버스 프록시·타임아웃·재시도로 흘렀다.
모두 로드맵 뒤쪽에 따로 있는 주제였다.

그래서 심화편에는 **같은 분야 블록에서 이 편 뒤에 오는 주제 이름**을 실어 "이름만 꺼내라"고 한다(`TopicQueue.laterTopicsInBlock`).
대기열은 분야별 블록으로 쌓여 있으므로, 이어지는 같은 분야 줄이 곧 이 흐름의 뒤 편이다. 분야가 바뀌는 줄에서 멈춘다.
주제 문장의 줄표(—) 뒤 출발 장면은 떼고 개념 이름만 준다.

### 그림 칸

입문편은 그림이 1개 이상이어야 한다(검증기 경고). 예전에는 "많아도 2개, 심화편 1개" 상한도 있었는데 근거 기록이 없어 지웠다.
틀린 그림은 화면에 원문 코드로 남을 뿐이고 같은 내용을 두 번 그리면 기존 중복 금지 규칙이 막는다.

로드맵 84편 중 82편에 그림을 지정했다. HTTP 생김새(코드 블록이 낫다)와 JOIN(표가 낫다)은 비워 두었다.
종류는 화면이 그릴 수 있는 셋만 쓴다.

| 괄호 | 화면 이름 | 쓰는 곳 |
|---|---|---|
| `flowchart` | 흐름도 | 갈래와 경로 |
| `sequenceDiagram` | 순서도 | 두 쪽이 주고받는 순서 |
| `stateDiagram-v2` | 상태도 | 상태가 바뀌는 과정 |

## 4. 관리 화면

| 화면 | 하는 일 |
|---|---|
| `admin/topics.html` | 순서 정하기. 차례·분야·주제·지시 요약·사용 칸과 ⤒ ↑ ↓, 여러 줄 맨 위로 |
| `admin/topic.html?id=` | 지시를 칸별로 넓게 보기, 수정, 실행값 복사, 이력 지우기, 삭제 |

목록의 "차례"는 **배치가 몇 번째로 꺼내나**(`position`)다. 규칙은 안 쓴 것 → 오래전에 쓴 것 → 내가 놓은 순서다.
쓴 주제는 마지막 사용일이 자리를 정하므로 이동 버튼을 잠근다. ↑ ↓는 안 쓴 주제끼리 자리를 바꾼다.

목록의 지시 칸은 요약만 보인다. 핵심 개념 두 줄과 "질문 N · 그림 ✓/—"이다.
형식이 안 맞는 메모에는 "지시 아님 · 모델에 안 실림"을 붙인다.

## 5. 남은 일

- 문서가 어느 주제에서 나왔는지 DB가 기록하지 않는다. 상세 화면에 "이 주제로 만든 문서" 링크를 두려면 문서에 칸을 더하고 배치도 고쳐야 한다.
- 인프라 4번(방화벽과 포트 열기)이 네트워크의 포트 원리(15번)보다 먼저 나온다. 네트워크 블록을 앞으로 옮길지 정하지 않았다.
