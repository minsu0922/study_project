# 02. 도메인 Enum 정의

> 원칙: **Java enum 상수는 영문, 화면 표기(displayName)는 한글.** DB에는 enum 이름(영문)을 `VARCHAR`로 저장(`@Enumerated(EnumType.STRING)`).
> `EnumType.ORDINAL` 금지 — 순서 바뀌면 데이터 깨짐(ADR 없이도 지키는 규칙).

## 쉽게 말하면

enum(이넘)은 **"정해진 보기 중에서만 고르게 하는 값"**이다. 🎯
예를 들어 문제의 난이도는 아무 글자나 넣는 게 아니라 "초급/중급/고급" 셋 중 하나여야 한다.
이렇게 보기를 코드로 못 박아 두면 오타나 이상한 값이 DB에 들어가는 걸 막을 수 있다.

두 가지만 기억하자:
- **코드에는 영문**(`BEGINNER`), **화면에는 한글**(`초급`)로 보여준다.
- DB에는 숫자 순서(0,1,2…)가 아니라 **이름 그대로 글자로 저장**한다. 순서로 저장하면 나중에 보기 순서만 바꿔도 기존 데이터가 전부 엉키기 때문.

**분야(Domain)만 예외다.** 2026-09-22부터 분야는 더 이상 enum이 아니라, 관리자 화면에서
직접 늘리고 줄이는 **등록부**다. 아래에서 따로 설명한다.

---

## 분야(Domain) — 등록부다, enum이 아니다

문제의 분야는 코드에 못 박힌 목록이 아니라 `domain_setting` 테이블의 **행 그 자체**다.
표에 있으면 분야이고, 없으면 분야가 아니다. 새 분야가 필요하면 관리자 화면
"분야 설정"([21-domain-settings](21-domain-settings.md))에서 **코드·이름·힌트** 세 값을
입력해 만든다.

| 값 | 뜻 | 나중에 고칠 수 있나 |
|---|---|---|
| 코드 | `NETWORK` 같은 영문 식별자. 기본키이자 5개 내용 표가 참조하는 외래키 값 | **못 고친다** |
| 이름 | 화면에 뜨는 한글 이름(`네트워크`) | 고칠 수 있다 |
| 힌트 | 모델에게 "이 분야는 어디까지인가"를 알려 주는 경계 설명 | 고칠 수 있다 |

코드를 못 고치는 이유는 배치가 수동 실행 때 받는 `--domain=` 입력값이자, 저장소에 커밋된
과거 생성 파일 속에 이미 박혀 있는 값이기 때문이다. 코드를 바꾸면 그 파일들과의 연결이
끊긴다. 이름을 바꾸고 싶으면 이름 칸을 쓰면 된다.

### 코드는 형식만 검사한다

식별자 타입은 `Domain` enum 자리를 이은 `DomainCode`(`global/common/DomainCode.java`) —
코드 문자열 하나를 감싼 record다.

```java
public record DomainCode(String value) {
    // 영문 대문자로 시작, 대문자·숫자·밑줄, 2~30자. 30은 컬럼 길이(VARCHAR(30))에서 온다.
    private static final Pattern FORMAT = Pattern.compile("^[A-Z][A-Z0-9_]{1,29}$");
    ...
}
```

**형식만 본다. 존재는 안 본다.** "그런 분야가 실제로 있나"는 DB의 사실이라 타입 하나가
알 수 없다. JSON에는 `@JsonValue`로 문자열 하나(`"domain": "NETWORK"`)로 실려 나가므로
API 계약은 enum 시절과 그대로다.

### 존재 확인은 외래키가 최종 방어선이다

enum이 하던 일은 둘로 나뉘었다.

| enum이 하던 일 | 이제 누가 맡나 |
|---|---|
| 엉뚱한 값을 분야 자리에 넘기지 못하게 | `DomainCode` 타입 — 컴파일러가 계속 막는다 |
| 없는 분야를 가리키지 못하게 | **외래키**(V20) — 문제·문서·생성 문제 초안·생성 문서 초안·주제 대기열 다섯 표가 `domain_setting.domain`을 참조한다 |

**이 구조를 고른 이유는 실제로 겪은 사고 때문이다.** 예전에는 `domain_setting.domain`
컬럼이 `Domain` enum을 `@Enumerated(EnumType.STRING)`으로 저장했는데, enum 변환이
**행을 읽는 순간** 일어났다. 그래서 enum에 없는 이름을 가진 행이 이 표에 단 하나만 있어도
`findAll()`이든 무엇이든 이 표에 대한 **모든** 일반 조회가 `IllegalArgumentException`으로
죽었다(2026-09-21, `FRONTEND_CS`를 enum에서 지웠을 때 실제로 겪었다 — [21](21-domain-settings.md)).
식별자를 문자열을 감싼 값 타입으로 바꾸면 변환 자체가 없어져 이 실패 모드가 사라지고,
"없는 분야를 막는 일"은 읽기 쪽이 아니라 쓰기 쪽(외래키)으로 옮겨 간다 — 모르는 코드는
애초에 들어올 수 없으므로, 있는 행이 읽다가 갑자기 못 읽히는 일 자체가 없어진다.

### 추가·삭제

- **추가**: 코드·이름을 입력하면 **꺼진 채로 순환 맨 끝에** 생긴다. 관리자가 힌트를 쓰고
  화면에서 직접 켜야 배치 순환에 들어간다.
- **삭제**: 문제·문서·생성 문제 초안·생성 문서 초안(거절된 것 포함)·주제 대기열, 이 다섯
  표 중 하나라도 그 코드를 쓰는 행이 있으면 거절된다(400). 옮기거나 숨기는 방법은 없다 —
  자세한 이유는 [21-domain-settings](21-domain-settings.md)에 있다.

### 기본 11개는 "처음 값"일 뿐, 상한이 아니다

빈 DB가 처음 뜰 때만 아래 11개로 채운다(`DefaultDomains`, `llm.support`). 이후로는
관리자가 화면에서 자유롭게 늘리고 줄인다 — 이 표가 더는 "코드가 정한 고정 개수"가 아니다.

| 코드 | 이름 | 비고 |
|---|---|---|
| `NETWORK` | 네트워크 | |
| `OS` | 운영체제 | |
| `DATABASE` | 데이터베이스 | |
| `DS_ALGORITHM` | 자료구조·알고리즘 | |
| `SYSTEM_DESIGN` | 시스템설계 | **돌아가는 시스템**의 구조 — 부하·확장·장애 |
| `SOFTWARE_ENGINEERING` | 소프트웨어공학 | **코드를 만들고 관리하는 절차** — 요구사항·UML·디자인 패턴·테스트 기법·형상관리·개발방법론 (정보처리기사 대비로 신설) |
| `SECURITY` | 보안 | |
| `LANGUAGE_RUNTIME` | 언어·런타임 | 순수 Java/JVM — GC·메모리·동시성 |
| `BACKEND_FRAMEWORK` | 스프링·백엔드 | Spring DI/AOP/트랜잭션, JPA, 커넥션 풀 등 (LLM 문제 생성 도입 시 신설 — docs/13) |
| `CLOUD_INFRA` | 클라우드·인프라 | |
| `INTEGRATED` | 통합시나리오 | 여러 도메인 결합 문제 |

> `FRONTEND_CS`(프론트엔드CS)는 2026-09-21에 이 초기값 목록에서 뺐다. 백엔드 면접 대비라는
> 목적과 맞지 않아 배치 후보에서도 빠져 있었고, 저장된 행이 6개 테이블 전부 0건이라 지워도
> 깨지는 조회가 없었다.

본코드에서 이 11개 코드 문자열을 직접 아는 곳은 `DefaultDomains` 하나뿐이어야 한다
(허용된 예외 하나는 DB·설정 파일 어느 쪽도 못 읽는 `PromptEvalCli`). 나머지는 전부
"지금 등록된 분야가 무엇인지"를 `DomainCatalog`에게 묻는다 — 그래야 관리자가 화면에서
분야를 추가·삭제해도 코드를 고칠 필요가 없다.

## API 요청에서의 표기

- 쿼리 파라미터·JSON 필드는 **영문 상수명(난이도·문제유형) 또는 분야 코드**를 그대로 사용
  (예 `?domain=NETWORK&level=BEGINNER`). 모양은 enum 시절과 같다.
- 화면 노출용 한글이 필요하면 응답 DTO에 `domainLabel` 등으로 displayName을 함께 내려준다.
- 형식이 틀린 값(난이도·문제유형·분야 코드 전부) → `400 VALIDATION_ERROR` (전역 예외처리,
  `04-response-format` 참고).
- **분야만 다르다**: 형식은 맞는데 등록되지 않은 코드일 때, 목록 필터는 조용히 빈 목록을
  돌려주고(없는 분야로 거르면 빈 목록이 자연스럽다), 문제·문서를 실제로 쓰는 요청은 400
  (`DOMAIN_003`)으로 막는다 — 자세한 경계는 [21-domain-settings](21-domain-settings.md) 참고.
