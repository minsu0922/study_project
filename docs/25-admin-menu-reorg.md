# 25. 관리 메뉴 개편 — 한 메뉴에 한 기능

관리 콘솔 메뉴를 다시 짰다(2026-10-15). 원칙은 둘이다. 한 화면에는 한 가지 일만 담고
같은 내용을 보여 주는 화면이 둘이면 하나로 합친다. 메뉴는 여섯 묶음 열다섯 화면이 됐다.

---

## 1. 왜 했나

콘솔은 2026-09-06에 세 묶음으로 정리했다([20](20-ui-redesign.md) §9). 그 뒤 기능이 붙을 때마다
가까운 화면에 끼워 넣다 보니, 화면 하나가 일을 둘 셋씩 하게 됐다.

| 화면 | 문제 | 종류 |
|---|---|---|
| 생성 실행 | 직접 생성 폼과 주제 대기열(개념·코드 탭)이 한 화면에 있었다 | 섞임 |
| 문제 | 등록·수정 폼 옆에 AI 일괄 작업(제목·오답 설명 채우기)이 붙어 있었다 | 섞임 |
| 현황 | 학습 통계, 출제 분포, AI 승인율, 할 일 타일이 한 화면이었다. 메뉴에도 없이 기둥 맨 위 글자로만 들어갔다 | 섞임·숨음 |
| 검수 | 개념 문제와 코드 문제가 한 목록에 섞였고 문서 초안은 그 아래로 밀렸다 | 섞임 |
| 현황의 AI 승인율 ↔ 배치 현황의 "② 나온 것이 승인됐나" | 둘 다 AI 초안 승인율이었다 | 중복 |
| 배치 현황 | 4일 주기 일일 배치만 보였고 주간 코드 문제 배치는 볼 곳이 없었다 | 빠짐 |

검수 요약 표가 옆으로 열다섯 칸까지 늘어난 것이 계기였다. 개념 문제와 코드 문제의 검수기는
지적 종류가 거의 겹치지 않는데, 한 표에 모아 두어 어느 행이든 절반 넘는 칸이 늘 비어 있었다.

## 2. 지금 메뉴

| 묶음 | 메뉴 | 화면 | 하는 일 |
|---|---|---|---|
| 할 일 | 검수 | `llm.html` | AI 초안 판정. 개념 문제·코드 문제·개념 문서 탭 |
| | 오류 제보 | `reports.html` | 문제가 틀렸다는 학습자 신호(제보 + 토론방 오류 지적) |
| | 게시글 신고 | `comments.html` | 토론 글·댓글 판정 |
| 콘텐츠 | 문제 | `problems.html` | 문제 등록·수정·목록 |
| | 문서 | `documents.html` | 문서 등록·수정·목록 |
| AI 생성 | 직접 생성 | `generate.html` | 지금 바로 Claude에게 문제를 만들게 한다 |
| | 주제 대기열 | `topics.html` | 배치가 쓸 개념 문서·코드 문제 주제와 그 차례 |
| | 일괄 보정 | `backfill.html` | 이미 있는 문제의 제목·오답 설명 채우기 |
| 배치 | 배치 현황 | `batch.html` | 일일 배치와 주간 코드 배치의 일정·결과 |
| | 분야 설정 | `settings.html` | 분야 켜기·끄기·순서·힌트 |
| 통계 | 학습 현황 | `index.html` | 이용 추이, 분야별·문제별 정답률 |
| | 출제 분포 | `distribution.html` | 분야 × 난이도 문제 수와 빈 칸 |
| | AI 품질 | `quality.html` | 초안 승인율. 최근 30일과 모델별 |
| 운영 | 사용자 | `users.html`·`user.html` | 목록과 상세 |
| | 처리 기록 | `audit.html` | 관리자가 한 쓰기 요청 |

"AI 생성" 묶음의 화면은 전부 Claude 요금과 이어진다. 직접 생성과 일괄 보정은 누를 때마다
요금이 나가고, 주제 대기열은 배치가 무엇에 요금을 쓸지 정한다.

## 3. 무엇을 옮겼나

| 옮긴 것 | 전 | 후 |
|---|---|---|
| 주제 대기열 | 생성 화면 아래 절 | 독립 화면. `?kind=CODE`로 코드 탭을 바로 연다 |
| 제목·오답 설명 채우기 | 문제 화면, 채울 것이 있을 때만 카드가 뜸 | 독립 화면. 늘 보이고 채울 것이 없으면 버튼만 잠근다. 남은 수는 메뉴 배지로도 보인다 |
| 이용 추이·정답률 | 현황 | 학습 현황 |
| 출제 분포 표 | 현황 | 출제 분포 |
| 모델별 승인율 | 현황 | AI 품질 |
| 최근 30일 승인 | 배치 현황 "②" | AI 품질 |
| 개념·코드 문제 초안 | 검수 화면의 한 목록 | 검수 화면의 탭 둘 |
| 개념 문서 초안 | 검수 화면 아래쪽 | 검수 화면의 셋째 탭 |

화면을 나누다가 원래 있던 결함 둘을 함께 고쳤다.

- 주제 대기열의 안내와 "복사" 버튼이 코드 문제 탭에서도 `_topics.json`과 일일 배치 워크플로를 가리켰다.
  지금은 탭에 맞는 파일(`_code-topics.json`)과 워크플로(LLM 코드 문제)를 말한다.
- 검수함 요약 표의 열 열다섯을 개념 문제 8열, 코드 문제 10열로 나눴다. 탭으로 갈린 뒤에는 한 목록에 한 종류만 뜬다.

## 4. 결정

**"할 일" 타일은 없앴다.** 옛 현황 화면 맨 위의 타일 셋(검수 대기, 빈 칸, 손볼 문제)과 배치 스위치 줄은
같은 내용을 다른 곳이 이미 보여 주고 있었다. 검수 대기는 검수 메뉴 배지, 손볼 문제는 일괄 보정 배지,
배치 스위치는 배치 현황이 맡는다. 빈 칸 수만 출제 분포로 옮겼다.

**콘솔 입구는 검수 화면이다.** 학습 화면의 "관리 콘솔" 링크가 현황으로 가던 것을 검수로 바꿨다.
콘솔에 들어오는 이유가 대개 검수할 것이 있어서다. 기둥 맨 위의 "현황" 글자 링크는 지웠다.
학습 현황이 메뉴에 들어왔기 때문이다.

**분야 설정의 "다음 7일"은 옮기지 않았다.** 처음 제안에서는 배치 현황의 주기 달력과 겹친다고 보고
배치 현황으로 옮기려 했다. 실제로 보니 이 칸은 분야를 켜거나 순서를 바꾸는 순간 다시 그려지는
**설정 미리보기**였다. 설정 화면을 떠나면 그 쓸모가 사라진다.

**옛 주소는 살린다.** `generate.html#topics`(검수 화면·북마크)는 주제 대기열로 넘긴다.
검수함의 `?kind=problem`(AI 품질 모델 표가 쓰는 주소)은 개념 문제 탭으로 연다.
`index.html`은 이름을 그대로 두고 학습 현황이 됐다. `/admin`이 이 파일로 넘어오기 때문이다.

## 5. 서버에 더한 것

| API | 쓰는 곳 | 내용 |
|---|---|---|
| `GET /api/admin/batch-status/code` | 배치 현황의 "주간 코드 문제" 카드 | 코드 주제 수, 다음 주제, 다음 실행 시각(일 02:47 KST), 날짜별 결과(주제·문제 수·검수 지적 수·들여오기 여부) |
| `GET /api/admin/llm-problems?code=true\|false` | 검수함 탭 | 값이 없으면 예전처럼 둘 다 |
| `GET /api/admin/badge-counts` | 콘솔 메뉴 배지, 검수함 요약·탭 숫자, 학습 화면의 관리 배지 | 배지에 쓰는 개수 전부 |

코드 배치 상태는 일일 배치의 `batch-status` 응답에 넣지 않고 따로 냈다. 주기·주제·결과 파일이
모두 달라서다. 한 응답에 섞으면 4일 주기 달력을 그리는 값들 사이에 주 1회 배치 값이 끼어든다.

## 6. 요청 한도에 걸렸다

개편을 마친 뒤 서버 로그에 이 줄이 찍혔다.

```
요청 제한 발동 key=rl:api:user:1 retryAfter=1s
```

`admin` 계정이 일반 API 한도(분당 60회)를 넘었다는 뜻이다. 콘솔 화면은 열 때마다 메뉴 배지 숫자를
세려고 개수 API를 따로따로 불렀는데, 개편으로 배지가 늘어 여섯 번이 여덟 번이 됐다. 검수 화면은
탭 숫자로 두 번을 더 불러, 한 번 열 때 요청이 13개쯤 나갔다. 1분 안에 화면을 대여섯 번 옮기면 한도를 넘는다.

| 고치는 방법 | 효과 | 결정 |
|---|---|---|
| 배지 개수를 API 하나로 합친다 | 검수 화면을 열 때 요청이 13개쯤에서 5개로 준다 | **함** |
| 관리자 한도를 넉넉하게 둔다 | 걸리지 않는다 | 안 함. 관리자 계정이 털렸을 때 막는 장치가 약해진다 |

`badge-counts`는 각 개수를 원래 API가 쓰던 서비스로 센다(`AdminBadgeService`). 새 쿼리를 따로 쓰면
배지와 각 화면의 숫자가 어긋날 수 있다. 응답을 받지 못하면 배지를 0으로 채우지 않고 그리지 않는다.
주제 대기열 배지는 0일 때 "범위 없음" 경고를 띄우므로, 0으로 채우면 거짓 경보가 된다.

## 7. 확인한 것

| 확인 | 방법 |
|---|---|
| 새 화면이 공통 규칙을 지키나 | `AdminPageStructureTest`의 검사 목록에 `topics`·`backfill`·`distribution`·`quality`를 넣었다. 넘겨주기 전용으로 빠져 있던 `topics.html`은 이제 일반 화면이다 |
| 화면이 그려지나 | 모듈마다 8081 확인용 앱에서 다크·라이트 두 테마로 봤다. 검수함 탭은 임시 코드 초안을 넣어 세 탭을 오가며 확인하고 지웠다 |
| 코드 조건이 맞게 거르나 | `CodeProblemWiringTest`(같은 질문의 코드 문제가 개념 탭에 섞이지 않는다), `AdminCodeBatchServiceTest`(다음 실행 시각, 날짜별 묶기), `AdminBadgeServiceTest` |
| 요청 수 | 검수 화면을 열 때 나간 API를 브라우저에서 셌다. 5개(분야 목록, 배지, 근거 문서 목록, 문제 초안, 문서 초안) |

## 8. 남은 일

| 일 | 상태 |
|---|---|
| 관리 화면을 1분에 열 번 넘게 옮기면 여전히 한도에 걸릴 수 있다 | 자주 걸리면 그때 관리자 한도를 따로 둔다 |
| 다른 설계 문서(14·16·21 등)의 옛 화면 이름 | "배치 탭", "생성 실행" 같은 말이 경위 기록으로 남아 있다. 그때의 이름이라 고치지 않았다 |
