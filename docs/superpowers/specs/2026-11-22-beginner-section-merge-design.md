# 입문편 절 통합 설계

## 목적

배치가 만든 입문편은 같은 내용을 여러 절에서 다시 설명한다. 2026-11-21 스프링 문서는 세 층의 역할을 9곳에서 설명했다.
이번 개편은 문장 규칙은 그대로 두고 절만 합친다. 중복 문장 제거는 다음 단계의 중복 검사가 맡는다. 문제 생성이 절 이름에 묶여 있으면 문제 생성 쪽을 새 구조에 맞춘다.

## 범위

| 구분 | 내용 |
|---|---|
| 한다 | 새로 만드는 입문편·심화편의 절 구조, 생성 프롬프트, 필수 절, 문제 재료 지목 |
| 하지 않는다 | 이미 나간 문서 재작성, 중복 문장 제거, AI 중복 제거 단계 |
| 실패로 본다 | 옛 문서가 승인이나 출제에서 막히는 일, 문제 재료가 조용히 사라지는 일 |

## 새 구조

```text
글의 주제
## 바탕이 되는 개념        주제 전 지식
## 무엇이고 왜 필요한가    정의 → 없을 때 문제 → 비유 대응표
## (본론)                  동작 순서, 왜 이렇게 설계됐는가
## 실무에서는 이렇게 쓴다  장면 하나 + ### 헷갈리기 쉬운 점
## 정리                    글의 주제에 답 + 결론 4~6줄 + ### 용어 한눈에
## 참고 자료
```

심화편은 아래 구조다.

```text
글의 주제
## 이 글을 읽기 전에
## (본론)
## 실무에서 어디에 나타나는가
## 어떤 때 통하지 않는가      장면 ①②③
## 면접에서 이렇게 물어본다   질문 + ### 흔한 오해
## 심화편 정리                대본 + 결론 4~6줄 + ### 용어 한눈에
## 참고 자료
```

## 검토한 방법

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 문제 재료를 건드리지 않는 절만 합치기 | 문제 생성 변경이 없다 | 중복이 많이 남는다 | 버림 |
| 절을 크게 합치고 문제 생성을 맞추기 | 중복을 가장 많이 줄인다 | 재료 지목을 함께 고쳐야 한다 | 사용자 선택 |
| 요약을 글 앞에 모으기 | 첫 화면에서 결론을 본다 | 끝맺는 절이 없어진다 | 버림 |
| 요약을 글 끝 「정리」에 모으기 | 글의 주제 바로 뒤의 반복이 사라진다 | 첫 화면에서 결론을 못 본다 | 사용자 선택 |

## 문제 생성과 다른 기능

| 자리 | 변경 |
|---|---|
| 초급 재료 | 바탕 + 새 절의 정의·역할 부분 + `### 용어 한눈에` |
| 중급 재료 | 왜 이렇게 설계됐는가 + 실무 절 전체 |
| 고급 재료 | 어떤 때 통하지 않는가 + 면접(흔한 오해 포함) |
| 다음 글 카드 | `## 정리`·`## 심화편 정리`의 첫 굵은 항목을 읽는다 |
| 검색 설명 | `## 정리`·`## 심화편 정리`의 첫 문단을 읽는다 |
| 옛 문서 | `## 무엇인가`나 `## 면접 한 줄 요약`이 있으면 옛 필수 절로 검사한다 |

중급 재료를 자르는 코드가 첫 `###`에서 멈춰서 11-21 실무 절 1,209자 중 76자만 실렸다. 이제 `##` 절은 다음 `##` 앞까지 자르고 코드블록 속 `#` 주석은 제목으로 보지 않는다.

## 확인

| 항목 | 입문편 | 심화편 |
|---|---|---|
| `##` 절 | 11개 → 7개 | 11개 → 9개 |
| 분량 | 15,105자 → 15,092자 | 20,052자 → 20,040자 |
| 검증기 차단·경고 | 0건 | 0건 |
| 짝짓기 재료 표 행 | 17행 | 16행 |

통합본은 11-21 두 편을 API 호출 없이 문장은 그대로 두고 절만 옮겨 만들었다. 새 프롬프트로 만든 실제 문서의 품질은 다음 배치나 유료 시험 생성으로 확인한다.
