# 백엔드 기술 지도 설계

2026-11-28. 사용자와 정한 내용과 내가 정한 값을 나눠 적는다. 내가 정한 값은 (내 판단)으로 표시한다.

## 왜 만드나

사용자가 두 가지를 한 화면에서 보길 원한다.

1. 백엔드 공부할 거리 전체가 어떤 모양인지 한눈에 본다.
2. 그 지도 위에서 내 진도를 색으로 보고, 다음에 읽을 문서로 바로 간다.

## 목표와 하지 않을 것

| 구분 | 내용 |
|---|---|
| 목표 | 분야 등록부에서 켜진 분야의 개념 주제(`kind=CONCEPT`) 전부를 점으로 그린다. 로드맵 전 옛 주제도 넣는다 |
| 하지 않음 | 배치가 꺼진 분야(지금은 소프트웨어공학)의 주제. 점이 늘 회색이라 뺀다 (사용자 결정) |
| 목표 | 점마다 내 진도를 색으로 칠한다 |
| 목표 | 점을 누르면 그 주제의 입문편·심화편 문서로 간다 |
| 하지 않음 | 84편 밖의 기술(Kafka 등)을 지도에 올리기. 사용자가 B안을 골랐다 |
| 하지 않음 | 자바 코드 문제 주제(`kind=CODE`). 문서가 없는 트랙이다 |
| 하지 않음 | 관리자 업로드 문서처럼 주제 없이 들어온 문서. 지도에 안 나온다 (내 판단) |
| 실패로 볼 것 | 문서가 나와도 점이 계속 회색이면 실패다. 연결이 자동이어야 한다 |

## 지금 구조와 막힌 곳

- 주제는 `topic_queue`(`kind=CONCEPT`)에 있다. 분야·주제 문장·순서(`sort_order`)가 있다.
- 배치는 GitHub Actions에서 DB 없이 돈다. `_topics.json`에서 주제를 골라 문서 파일을 쓰고, `_topic-usage.json`에 주제 id와 날짜를 찍는다.
- 앱은 기동할 때 `DocumentImportService`로 문서 파일을 들여온다.
- **문서와 주제를 잇는 값이 어디에도 없다.** 문서 파일(`GeneratedDocumentFile`)에도, `document` 테이블에도 주제 id가 없다.
- 진도는 학습 로드맵이 이미 계산한다. `LearningPathStatsRepository.countProblemsBySlug`·`progressBySlug`가 문서 slug별 문제 수와 내 제출·맞힌 수를 준다.

## 고른 방법

| 안 | 내용 | 결과 |
|---|---|---|
| 1. 문서에 주제 번호 칸 추가 | 배치가 문서 파일에 주제 id를 찍고, 들여올 때 `document.topic_id`에 넣는다 | **사용자가 골랐다** |
| 2. 제목으로 짝짓기 | 주제 문장과 문서 제목을 비교 | 버림. 문서 제목 규칙(명사구)과 주제 문장이 달라 거의 안 맞는다 |
| 3. 지도 파일 따로 | 사람이 주제→slug 표를 관리 | 버림. 문서가 나올 때마다 손으로 고쳐야 한다 |

지도 점 범위는 사용자가 B안(주제 로드맵 전체, 안 쓴 주제도 회색)으로 골랐다. 실제 주제는 84편이 아니라 개념 주제 102개(10분야)라서, 켜진 분야의 주제로 다시 정했다.

## 설계

### 1. 주제 번호 칸

- 마이그레이션: `document.topic_id BIGINT NULL`, `topic_queue(id)` 외래키, `ON DELETE SET NULL` (내 판단: 주제를 지워도 문서는 남아야 한다).
- 한 주제에 문서가 여러 쌍일 수 있다. 옛 범위형 주제는 여러 번 쓰였다. 그래서 UNIQUE를 걸지 않는다.

### 2. 배치가 주제 id를 찍는다

- `TopicQueue.Picked`에 주제 id를 더하고, 문서 파일에 `topicId` 칸을 더해 넣는다.
- id가 없으면(손으로 적은 대기열 줄, `--topic`으로 직접 준 주제) null로 둔다. 관리 화면에서 잇는다.
- 손으로 쓰는 흐름(하네스·서브에이전트)도 같은 칸을 채운다.
- 들여오기는 문서가 아니라 초안(`GeneratedDocumentDraft`)에 저장한다. 그래서 초안에도 `topic_id` 칸을 두고, 승인(`LlmDocumentService.approve`)할 때 `document.topic_id`로 옮긴다.
- 입문편·심화편 둘 다에 넣는다. 칸이 없는 옛 파일은 null로 둔다.

### 3. 이미 나간 문서 잇기 (백필)

- `_topic-usage.json`의 (주제 id, `lastUsedAt`, 분야)와 문서 파일의 (날짜, 분야)를 맞춰 잇는다.
- 한 번만 도는 관리 API로 만든다 (내 판단: 기동마다 돌 이유가 없다). 결과로 이은 수·못 이은 주제 목록을 돌려준다.
- 지금 사용 기록 39줄은 모두 같은 날짜·분야의 문서 파일과 하나씩 짝이 맞는다. 두 번 이상 쓴 주제는 없다.
- `topic_queue`에 없는 주제 id(지금 10, 11)는 건너뛰고 못 이은 목록에 남긴다. 외래키 위반을 막는다.
- 남는 문서는 12편이다. 사용 기록 전 문서 10편과 지운 주제로 쓴 2편이다.
- 이 12편은 관리 문서 화면에서 지금 있는 주제를 골라 손으로 잇는다. 맞는 주제가 없으면 잇지 않아 지도에서 빠진다 (사용자 결정).
- 관리 문서 화면에는 주제 선택 칸 하나만 더한다.

### 4. 지도 API

`GET /api/map` (공개, 토큰 있으면 내 진도를 싣는다. 학습 로드맵과 같은 방식)

```json
{
  "domains": [
    {
      "code": "NETWORK", "label": "네트워크",
      "topics": [
        {
          "id": 10, "title": "TCP와 UDP",
          "documents": [{"slug": "...", "title": "...", "edition": "BEGINNER"}],
          "problemTotal": 10, "attempted": 4, "solved": 3
        }
      ]
    }
  ]
}
```

- `edition`은 테이블 칸이 없다. 본문으로 가리는 `ClaudeDocumentGenerator.editionOf`와 같은 규칙을 쓴다.
- 분야 순서는 분야 등록부 순서, 주제 순서는 `sort_order`를 따른다.
- 점 이름은 주제 문장이 길어서 쓰기 어렵다. 이어진 입문편 문서 제목을 쓰고, 문서가 없으면 주제 문장을 줄여 쓴다 (내 판단).
- 진도는 그 주제에 이어진 공개 문서들의 문제를 합산한다. 기존 두 쿼리를 그대로 쓴다.
- 쿼리는 주제 수와 상관없이 3번이다(주제·문서, 문제 수, 내 제출).

### 5. 화면 `map.html`

- 가운데 「백엔드」, 둘레에 켜진 분야, 분야 둘레에 주제 점. 분야 수는 등록부에서 읽고 고정하지 않는다. SVG로 직접 그린다. 라이브러리는 넣지 않는다.
- 색 네 단계:

| 상태 | 조건 | 색 |
|---|---|---|
| 준비 중 | 이어진 문서가 없음 | 회색, 누르면 "준비 중" |
| 안 품 | 문서는 있고 `attempted = 0` | 흰 바탕 테두리 |
| 푸는 중 | `0 < solved < problemTotal` | 연한 분야색 |
| 다 품 | `solved = problemTotal > 0` | 진한 분야색 |

- 점을 누르면 옆 칸에 주제 이름, 진도 숫자, 입문편·심화편 링크가 뜬다.
- 비로그인이면 색 없이 준비 중/있음 두 가지만 보이고 "로그인하면 진도가 칠해진다"는 안내를 띄운다.
- 휴대폰 폭에서는 원형 대신 분야별 접는 목록으로 보인다 (내 판단: 84점 원형은 좁은 화면에서 못 누른다).
- 상단 메뉴에 「기술 지도」를 더한다.

## 작업 순서 (모듈)

1. 마이그레이션(문서·초안 두 테이블) + 엔티티 칸 + 들여오기·승인에서 `topicId` 옮기기 + 테스트
2. 배치·손으로 쓰는 흐름이 `topicId` 찍기
3. 백필 API + 관리 문서 화면 주제 선택 칸
4. 지도 API + 테스트
5. `map.html` + 메뉴
