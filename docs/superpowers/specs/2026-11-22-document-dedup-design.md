# 개념 문서 중복 검사 설계

2026-11-22 · 상태: 사용자 검토 대기

## 왜 하는가

배치 문서는 같은 내용을 여러 절에서 다시 설명한다. 2026-11-21 스프링 입문편은 세 층의 역할을 9곳에서 설명했고 심화편은 핵심 요약 5줄과 면접 5문항이 같은 내용이었다.
절 통합(`2026-11-22-beginner-section-merge-design.md`)은 절의 수만 줄였다. 문장 중복은 그대로 남아 있어 이 단계가 지운다.

최근 8개 주제 16편을 재 보니 표현까지 거의 같은 문장은 2,414개 중 24개(1.0%)였다. 대부분은 같은 내용을 다른 말로 쓴 중복이라 글자 비교로는 못 찾는다. 찾는 일은 AI가 맡고 지워도 되는지는 코드가 판정한다.

## 목표

1. 배치가 입문편과 심화편을 만든 직후 편마다 중복 문장을 찾아 자동으로 지운다.
2. 지운 문장 때문에 수치·조건·코드·문제 재료가 사라지지 않게 한다.
3. 지운 문장과 남긴 문장을 나란히 검수 화면에서 확인하고 필요하면 사람이 되살린다.

## 하지 않을 것

- 문장을 합쳐 새로 쓰기. 없던 내용이 섞일 수 있다.
- 입문편과 심화편 사이의 중복 지우기. 심화편의 「이 글을 읽기 전에」는 입문편을 일부러 다시 짚는 자리다.
- 이미 승인되어 나간 문서에 돌리기.
- 중복 검사 결과로 승인 막기.

## 실패로 칠 것

- 지운 문장에만 있던 수치, 조건, 코드 이름, 용어 정의가 글에서 사라진다.
- 뒷문장이 지운 문장을 "이", "그래서"로 받아 글이 끊긴다.
- 중급·고급 문제가 읽는 구역에서 재료가 빠진다.
- 중복 검사가 실패했다고 문서 저장이나 배치 job이 실패한다.
- 원본을 잃어 무엇을 지웠는지 되짚을 수 없다.

## 검토한 방법

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 윤문 앞 별도 단계 | 삭제만 따로 검사하고 윤문을 켜고 끌 수 있다 | 문서일마다 호출 2회와 순차 단계 1개가 는다 | 사용자 선택 |
| 윤문 호출에 넣기 | 호출이 늘지 않는다 | 삭제가 윤문 보존 대조에 걸리면 그 편의 윤문 전체를 버린다 | 버림 |
| 독자 점검의 되풀이 지적을 자동 적용 | 새 호출이 없다 | 윤문 뒤에 돌고 재료 절을 예외로 두어 많이 놓친다 | 버림 |
| 글자 유사도로 찾기 | 요금이 없다 | 표현이 다른 중복을 못 찾는다 | 버림 |

## 설계

### 1. 배치 단계 위치

```text
생성(입문·심화) → 파일 저장
  → [중복 검사 입문 · 중복 검사 심화] 동시에
  → 윤문 → 보존 대조 → reportDraftChecks
  → [사실 검수 · 독자 점검] 동시에
```

두 편은 동시에 보낸다. 배치 호출은 편마다 최대 45분이고 job 한도는 300분이라, 순차 단계가 하나 늘어도 한도 안에 드는지 평가 때 잰다.

### 2. AI가 하는 일

새 프롬프트 `prompts/document-dedup/system.txt`로 편마다 한 번 호출한다. 호출 설정은 독자 점검과 같고 웹 검색은 쓰지 않는다.

AI는 뒤에 나온 문장이 앞 문장의 내용을 새 정보 없이 다시 말할 때만 짝을 낸다. 고쳐 쓰지 않고 본문에서 글자 그대로 옮긴다.

```json
{
  "removals": [
    {
      "target": "지울 문장. 본문에 한 번만 나온다.",
      "kept": "같은 내용을 먼저 설명한 문장. 본문에 한 번만 나온다.",
      "reason": "새 정보가 없는 까닭 한 문장"
    }
  ]
}
```

### 3. 지울 수 있는 자리

문단 안의 일반 문장만 지운다. 아래 자리는 코드가 막는다.

| 막는 자리 | 이유 |
|---|---|
| 제목, 「글의 주제」, 인용 상자 | 형식과 사람이 쓴 글을 지킨다 |
| 「이 글을 읽기 전에」, 「정리」, 「심화편 정리」, 「참고 자료」 | 일부러 다시 말하는 자리다 |
| 코드, 그림, 표, 목록 | 한 줄을 지우면 구조가 깨진다 |
| `##` 절의 첫 문장 | 앞 절과 잇는 문장이다 |
| 그림·코드 바로 앞뒤 문장 | 무엇을 볼지 알려 주는 문장이다 |
| 굵은 글씨로 용어를 처음 푸는 문장 | 용어 정의가 사라진다 |
| 심화편 실무 항목, 꼬리표 항목, 면접 답변, 오해 항목 | 문제 재료이자 형식이 정해진 자리다 |

### 4. 코드 안전 검사

제안마다 아래를 모두 통과해야 지운다. 하나라도 걸리면 그 제안만 버린다.

| 검사 | 통과 조건 |
|---|---|
| 위치 | `target`과 `kept`가 본문에 각각 정확히 한 번 있다(`TextSpans.locateOnce`) |
| 순서 | `kept`가 `target`보다 앞에 있다 |
| 문장 경계 | `target`이 문장 하나 또는 이어진 문장 전체다 |
| 자리 | 3절의 막는 자리가 아니다 |
| 사실 보존 | `target`의 수치, 인라인 코드, 정도 부사(`CONDITION_WORDS`), 가능 표현이 `kept`에도 있다 |
| 뒷문장 | 바로 뒤 문장이 "이", "그", "그래서", "그러면", "이때", "반면"으로 시작하지 않는다 |
| 재료 구역 | 5절의 구역 규칙을 지킨다 |

### 5. 재료 구역

문제 생성은 난이도마다 읽는 본문이 다르다. `kept`가 다른 구역에 있으면 지운 내용이 그 난이도의 재료에서 사라진다.

| 편 | 구역 | 규칙 |
|---|---|---|
| 입문편 | `### 왜 이렇게 설계됐는가`, `## 실무에서는 이렇게 쓴다` | 중급으로 오려 가는 자리다. `kept`도 같은 구역에 있어야 지운다 |
| 입문편 | 나머지 | 초급은 입문편 전체를 읽으므로 `kept`가 어디 있어도 된다 |
| 심화편 | `## 실무에서 어디에 나타나는가` | 중급 재료다. `kept`도 이 절에 있어야 지운다 |
| 심화편 | `## 어떤 때 통하지 않는가`, `## 면접에서 이렇게 물어본다` | 고급 재료다. `kept`도 이 구역에 있어야 지운다 |
| 심화편 | 본론 | `kept`가 어디 있어도 된다 |

### 6. 채택 기준과 실패 처리

| 상황 | 처리 |
|---|---|
| 호출 실패, 응답 형식 오류 | 그 편은 원본을 쓰고 job은 계속한다 |
| 통과한 제안이 없다 | 그 편은 원본을 쓴다 |
| 지울 글자가 그 편의 10%를 넘는다 | 과하게 지운 응답으로 보고 그 편은 원본을 쓴다 |
| 적용 뒤 검증기에 새 차단·경고가 생긴다 | 그 편은 원본을 쓴다 (`PolishStep.newWarnings`와 같은 기준) |
| 문단의 문장이 모두 지워진다 | 빈 줄까지 함께 지운다 |

Actions 요약에는 편마다 `중복 n건 제거(m자) · 버린 제안 k건`과 버린 까닭을 남긴다.

### 7. 파일, DB, 화면

| 자리 | 변경 |
|---|---|
| 배치 파일 | `dedupRemovals`(편별 `removed`·`kept`·`section`·`reason`)를 더한다. 안 돌린 날은 칸을 쓰지 않는다 |
| 원본 칸 | `originalDocument`·`originalAdvancedDocument`는 처음 생성한 글로 고정한다 |
| DB | `V50`으로 `generated_document_draft.dedup_removals_json`을 더한다 |
| 나란히 검수 | 「중복 제거」 탭에 지운 문장, 남긴 문장, 이유를 보여 준다 |
| 되살리기 | 지운 문장 복사 단추를 두고 기존 「직접 고치기」로 문단에 넣는다 |

지금 `applyPolish`는 윤문 전 글을 원본 칸에 넣고 채택하지 않은 편의 원본 칸을 `null`로 비운다. 그대로 두면 중복 제거본이 원본으로 기록되거나 원본이 지워진다. 이미 원본 칸이 있으면 유지하도록 고친다.

윤문이 뒤에서 문장을 바꾸므로 지운 자리는 나중에 글자로 찾을 수 없다. 그래서 자동 되살리기 API는 이번에 만들지 않는다.

### 8. 설정과 켜는 순서

`llm.generation.dedup-enabled: false`를 더한다. 키가 없으면 끈다.

1. 코드를 main에 올리고 로컬 앱을 먼저 갱신한다. 문서 파일과 DB 칸이 늘어난다.
2. `evalDedup`으로 최근 문서를 평가한다. 실제 API 호출이므로 횟수와 예상 비용을 적고 승인을 받는다.
3. 지운 문장을 사람이 읽고 결과가 좋으면 `dedup-enabled`를 켠다.

### 9. 평가 기준

세 주제 6편을 원본과 제거본으로 나란히 본다.

| 항목 | 통과 기준 |
|---|---|
| 잘못 지운 문장 | 0건 |
| 재료 | 난이도별 재료 판정이 그대로이고 짝짓기 표 행이 줄지 않는다 |
| 효과 | 사람이 읽어 남은 중복이 줄었다고 판단한다 |
| 분량 | 편마다 10% 이내로 줄어든다 |
| 시간 | job이 300분 한도 안에 끝난다 |

## 사용자 결정

- AI가 중복을 자동으로 지운다.
- 윤문 안이 아니라 윤문 앞 별도 단계로 둔다.
- 문서 절 통합을 먼저 하고 중복 제거를 그 뒤에 한다.

## 설계자가 정한 값

- 한 편에서 지울 수 있는 상한은 10%다. 2026-11-21 문서를 사람이 줄였을 때 6~9%였던 값을 보고 정한 시작값이며 평가 뒤 다시 잡는다.
- 입문편과 심화편 사이의 중복은 범위에서 뺐다.
- 자동 되살리기는 만들지 않고 복사와 직접 고치기로 처리한다.
