# 분야 등록부 — 화면에서 분야 추가·삭제 설계

작성일: 2026-09-22
선행 작업: `docs/superpowers/specs/2026-09-21-domain-settings-cms-design.md`(분야 설정 관리창), `docs/21-domain-settings.md`

관리자 화면에서 분야(도메인)를 **새로 만들고 지울 수 있게** 한다. 지금은 분야 목록이
`Domain` enum에 박혀 있어서, 분야 하나를 더하려면 코드를 고쳐 다시 배포해야 한다.

---

## 1. 무엇을 하고, 무엇을 하지 않나

| 한다 | 하지 않는다 |
|---|---|
| 화면에서 분야 추가(코드·이름·힌트) | 분야 **코드** 수정 — 이름과 힌트만 고친다(5절) |
| 화면에서 분야 삭제 — 내용이 없을 때만 | 내용이 있는 분야를 지우는 방법(옮기기·숨기기) — 사용자가 "막기"를 골랐다 |
| 이름을 한곳에서 읽게 — 지금 화면마다 이름이 갈리는 버그 수정(6절) | 분야별로 다르게 동작하는 규칙(분야마다 다른 문제 수 등) |

**삭제 방식은 사용자 결정이다(2026-09-22).** 후보는 셋이었다 — 옮기고 삭제, 내용 있으면
막기, 숨김(보관). "막기"를 골랐다. 가장 단순하고, 숨김처럼 모든 목록 조회에 "숨김 제외"
조건을 붙일 필요가 없다. 내용이 쌓인 분야는 **끄기**로 순환에서 빼면 된다(이미 있는 기능).

## 2. 지금 `Domain` enum이 실제로 하는 일 — 조사 결과

바꾸기 전에 enum이 어떻게 쓰이는지 종류별로 셌다. 결론은 **enum이 거의 "이름표" 노릇만
한다**는 것이고, 그래서 이 작업의 대부분이 기계적인 타입 교체다.

| 쓰임새 | 개수 | 뜻 |
|---|---|---|
| `Domain`을 import하는 본코드 파일 | 69 | 대부분 필드·인자·반환 타입 |
| 같은 테스트 파일 | 52 | 대부분 `Domain.NETWORK` 같은 고정값 |
| `switch (domain)` | **0** | 분야에 따라 갈라지는 로직이 없다 |
| 특정 상수를 본코드에 박은 곳 | **5** | 내장 힌트 4개(`DomainHints.BUILT_IN`) + `PromptEvalCli` 폴백 1개 |
| `Domain.values()` / `valueOf` | 12 | "전체 분야" 또는 문자열 해석 |
| enum의 `getDisplayName()` | 12 | 응답 DTO 9곳 + 프롬프트 3곳 — **6절의 버그 원인** |
| 엔티티 필드 | 6 | 문제·문서·문제 초안·문서 초안·주제 대기열·분야 설정 |
| 요청값으로 받는 곳 | 16 | 컨트롤러 파라미터 11 + 요청 DTO 5 |

`switch`가 0이고 박힌 상수가 5개뿐이라는 것이 이 설계의 전제다. 본코드가 **특정 분야를
몰라도 되는** 구조가 이미 거의 완성돼 있다.

DB는 이미 준비돼 있다. 여섯 표의 `domain` 컬럼이 전부 `VARCHAR(30)`, `utf8mb4`,
`utf8mb4_0900_ai_ci`, InnoDB이고 코드 글자를 그대로 담고 있다(`EnumType.STRING`).
**데이터 이전이 필요 없다.** 그리고 설정 표에 없는 코드를 쓰는 행이 현재 0건이다(2026-09-22 실측).

## 3. 접근법 — 값 타입 + 외래키

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 값 타입 + 외래키** | enum을 `DomainCode`(코드 문자열 하나를 감싼 record)로 교체. 어떤 분야가 있는지는 `domain_setting` 표가 정하고, 내용 표 5개가 외래키로 그 표를 가리킨다 | **채택** |
| B. 그냥 `String` | enum 자리에 문자열 | 분야 코드와 주제 문자열이 둘 다 `String`이라, 자리를 바꿔 넘겨도 컴파일된다 |
| C. enum 유지 + 추가분만 표 | 기본 11개는 enum, 새로 만든 것만 DB | 분야가 두 종류가 되어, 읽는 곳마다 둘을 합쳐야 한다. 합치기를 한 곳에서 빠뜨리면 그 화면에만 새 분야가 안 보인다 |

A는 enum이 하던 일 둘을 나눠 맡긴다.

| enum이 하던 일 | 이제 누가 |
|---|---|
| 엉뚱한 값을 분야 자리에 넘기지 못하게 | `DomainCode` 타입 — 컴파일러가 계속 막는다 |
| 없는 분야를 가리키지 못하게 | **외래키** — DB가 막는다 |

그리고 외래키가 덤으로 두 가지를 해결한다.

1. **"내용 있으면 삭제 막기"를 DB가 강제한다.** 삭제 API가 개수 확인을 빠뜨려도 DB가 거부한다.
2. **"모르는 분야 한 줄이 있으면 조회가 전부 터지는" 문제가 사라진다.** 그 문제는 enum 변환이
   읽는 즉시 일어나서 생겼다(docs/21). 문자열을 감싼 값 타입에는 변환 실패가 없고, 외래키 때문에
   애초에 모르는 코드가 들어올 수도 없다. 기동 시 네이티브 질의로 고아 행을 지우던 우회
   (`findAllDomainNamesNative` 등)도 필요 없어진다.

## 4. 핵심 구조

### 4.1 `DomainCode` — 코드 한 개를 감싼 값 타입

```java
public record DomainCode(String value) {
    // 영문 대문자로 시작, 대문자·숫자·밑줄, 2~30자. 30은 컬럼 길이(VARCHAR(30))에서 온다.
    private static final Pattern FORMAT = Pattern.compile("^[A-Z][A-Z0-9_]{1,29}$");
    public DomainCode { /* FORMAT 검사, 어긋나면 IllegalArgumentException */ }
    public static DomainCode of(String raw) { ... }
    @JsonValue public String value() { ... }         // JSON에는 "NETWORK" 그대로
    @JsonCreator static DomainCode fromJson(String raw) { ... }
}
```

- **형식만 검사한다. 존재 여부는 검사하지 않는다.** 존재는 DB의 사실이라 값 타입이 알 수 없다.
  존재 확인은 쓰는 경로에서 따로 한다(7절).
- **대문자만 허용하는 이유:** 정렬 규칙 `utf8mb4_0900_ai_ci`가 대소문자를 구별하지 않는다.
  `network`와 `NETWORK`를 둘 다 허용하면 기본키 충돌이 "이미 있음"이라는 알 수 없는 오류로 나온다.
  형식에서 막으면 그 경우가 아예 생기지 않는다.
- **JSON 모양이 그대로다.** 지금 API는 `"domain": "NETWORK"`로 주고받는다. `@JsonValue`로
  문자열 하나로 직렬화하므로 **외부 API 계약이 바뀌지 않는다.** 화면·배치 파일·생성 결과 파일
  어느 것도 고칠 필요가 없다.
- 엔티티는 `AttributeConverter<DomainCode, String>`(autoApply)로 저장한다. 컬럼 값은 지금과 같다.
- 스프링 MVC 바인딩(`@RequestParam`·`@PathVariable`)용 `Converter<String, DomainCode>`를 등록한다.
  형식이 틀리면 지금 enum 변환 실패와 같은 400이 난다.

### 4.2 `domain_setting`이 등록부가 된다

지금 `domain_setting`은 "enum을 따라가는 설정 표"다. 이제 **그 표가 곧 분야 목록이다.**
표에 있으면 분야이고, 없으면 분야가 아니다.

```sql
-- V20__domain_foreign_keys.sql
ALTER TABLE problem                  ADD CONSTRAINT fk_problem_domain  FOREIGN KEY (domain) REFERENCES domain_setting (domain);
ALTER TABLE document                 ADD CONSTRAINT fk_document_domain FOREIGN KEY (domain) REFERENCES domain_setting (domain);
ALTER TABLE generated_problem_draft  ADD CONSTRAINT fk_gpd_domain      FOREIGN KEY (domain) REFERENCES domain_setting (domain);
ALTER TABLE generated_document_draft ADD CONSTRAINT fk_gdd_domain      FOREIGN KEY (domain) REFERENCES domain_setting (domain);
ALTER TABLE topic_queue              ADD CONSTRAINT fk_topic_domain    FOREIGN KEY (domain) REFERENCES domain_setting (domain);
```

- `ON DELETE`는 기본값(RESTRICT)이다. 이것이 "내용 있으면 삭제 막기"다.
- `ON UPDATE`도 기본값이다. 코드는 바꾸지 않으므로(5절) 연쇄 수정이 필요 없다.
- **스키마만 담는다**(docs/11). 행을 넣지 않는다.
- **이 마이그레이션이 실패할 수 있는 경우는 하나다.** 내용 표에 설정 표에 없는 코드가 있을 때다.
  지금 DB는 0건이다(실측). 하지만 V19만 적용되고 앱이 한 번도 안 뜬 DB라면 설정 표가 비어 있다.
  그때 내용 표에 행이 있으면 외래키 추가가 실패한다. V20은 외래키를 걸기 전에 **내용 표에
  나오는 코드 중 설정 표에 없는 것을 꺼진 행으로 먼저 채운다**(이름 = 코드). 콘텐츠를 심는 것이
  아니라 이미 있는 데이터가 스스로 일관되게 만드는 것이라, "Flyway엔 스키마만" 규칙의 취지와
  어긋나지 않는다. 판단 근거를 마이그레이션 주석에 남긴다.
- `domain_stats`는 뷰라 외래키 대상이 아니다.

### 4.3 `DomainCatalog` — 분야 정보를 읽는 단일 창구

지난 작업에서 만든 `DomainHintsProvider`(힌트만 준다)를 넓힌다.

```java
public interface DomainCatalog {            // llm.support — 생성기가 서비스 계층을 몰라도 되게
    List<DomainEntry> all();                 // 순서(sortOrder)대로, 꺼진 것 포함
    List<DomainCode> enabled();              // 순환 후보, 순서대로
    String displayName(DomainCode code);     // 없으면 코드 문자열 그대로
    DomainHints hints();
    boolean exists(DomainCode code);
}
```

| 구현 | 어디서 읽나 | 누가 쓰나 |
|---|---|---|
| 앱 — `DomainSettingService` | DB | 서비스·DTO·스프링이 만든 생성기 |
| 배치 — `DomainSettings` | `generated/_domain-settings.json` | CLI, CLI가 만든 생성기 |
| 테스트 — 상수 목록 | 코드 | 단위 테스트 |

`DomainHintsProvider`는 이 인터페이스로 흡수한다. **힌트뿐 아니라 이름도 쓰는 순간에 읽는다**
(지난 작업의 I-2 결론 — 생성 시점에 한 번 읽으면 재시작해야 반영된다).

배치 파일에는 이미 이름·힌트·켜짐·순서가 다 들어 있다. 새 칸이 필요 없다.

### 4.4 "전체 분야"의 뜻

`Domain.values()`(12곳)가 사라지면 "전체"를 따로 정해야 한다.

| 어디서 | "전체" = |
|---|---|
| 앱 | 설정 표의 모든 행 |
| 배치 — 설정 파일 있음 | 파일의 모든 항목 |
| 배치 — 파일 없음 | `application.yml`의 `batch-domains` |
| 배치 — 둘 다 없음 | `DefaultDomains`(8절)의 코드 11개 |

마지막 줄이 있어야 설정 파일이 없는 새 저장소에서도 배치가 돈다.

## 5. 추가·수정·삭제 규칙

| 동작 | 규칙 | 이유 |
|---|---|---|
| **추가** | 코드·이름·힌트 입력. **꺼진 채로** 순서 맨 끝에 생긴다 | 켜는 순간 순환이 밀린다. 힌트를 쓰고 7일 미리보기를 본 뒤 켜게 한다 |
| 추가 — 코드 형식 | `^[A-Z][A-Z0-9_]{1,29}$`, 중복이면 400 | 4.1 — 대소문자 충돌을 형식으로 막는다 |
| 추가 — 이름 | 필수, 40자 이하(지금 규칙 그대로) | |
| **수정** | 이름·힌트·켜짐·순서만. **코드는 바꿀 수 없다** | 코드는 기본키이자 외래키 대상, 배치 수동 실행의 `domain` 입력값, 저장소에 커밋된 생성 파일 속 값이다. 바꾸면 과거 파일과의 연결이 끊긴다. 이름을 바꾸고 싶은 것이라면 이름 칸이 있다 |
| **삭제** | 아래 다섯 표에 그 코드를 쓰는 행이 **한 건이라도** 있으면 400. 어느 표에 몇 건인지 알려 준다 | 사용자 결정(1절) |
| 삭제 — 세는 대상 | 문제, 문서, 문제 초안, 문서 초안(**거절된 것 포함**), 주제 대기열 | 외래키가 다섯 표 모두에 걸리므로 셈도 같아야 한다. 거절된 초안은 모델에게 되먹이는 거절 사례의 원천이라 지우지 않는다 |
| 삭제 — 마지막 켜진 분야 | 불가(지금 규칙 그대로) | 배치 정지 스위치는 `batch-enabled` 하나 |
| 삭제 — 기본 분야 11개 | **특별 취급하지 않는다** | 내용이 없으면 지울 수 있다. 기본값이라는 이유로 지울 수 없게 하면 "등록부"가 아니라 "enum + 추가분"(3절의 C안)이 된다 |

**삭제 거부 메시지 예:**
```
'클라우드·인프라'를 지울 수 없습니다 — 주제 대기열 4건이 이 분야를 씁니다.
순환에서만 빼려면 체크를 끄세요.
```

**경쟁 조건.** "개수 확인 → 삭제" 사이에 누가 그 분야로 문제를 만들면 외래키가 삭제를 거부한다.
관리자가 한 명이라 사실상 일어나지 않고, 일어나도 DB가 막으니 데이터는 안전하다. 그 경우에 한해
오류가 500으로 보일 수 있는데, 받아들인다.

## 6. 함께 고치는 버그 — 화면마다 분야 이름이 다르다

**지금 이미 나가 있는 버그다(2026-09-22 발견).** 분야 설정 화면에서 이름을 바꾸면 필터 목록
(`GET /api/domains`)에는 반영된다. 하지만 아래 12곳은 enum에 박힌 옛 이름을 계속 쓴다.

| 곳 | 보이는 자리 |
|---|---|
| `ProblemListService:159` | 문제 목록 사이드바 |
| `ReviewListItem:43`, `ReviewTodayItem:56` | 복습 목록·오늘 복습 |
| `DocumentDetailResponse:52`, `DocumentRepositoryImpl:107` | 문서 상세·문서 목록 |
| `TopicQueueItemResponse:39`, `LlmDocumentService:269`, `LlmProblemService:690`, `DomainTitle:21` | 관리 화면 여러 곳 |
| `ClaudeProblemGenerator:809`, `ClaudeDocumentGenerator:1293·1400` | **모델에게 보내는 프롬프트**의 "분야: …" |

마지막 줄이 가장 나쁘다. 이름을 바꾸면 힌트는 새것인데 분야 이름은 옛것인 프롬프트가 나간다.

enum이 사라지면 `getDisplayName()`도 없어지므로, 12곳 모두 `DomainCatalog.displayName(code)`로
바꿀 수밖에 없다. **이 버그는 이번 작업의 부산물로 저절로 고쳐진다.** 다만 전부 한 번에 바뀌므로,
구현 계획에서 이 12곳을 따로 한 태스크로 묶고 "바꾼 이름이 이 자리에 보이는가"를 테스트로 박는다.

## 7. 경계 — 바깥에서 분야 코드가 들어오는 곳

| 들어오는 곳 | 개수 | 형식 검사 | 존재 검사 |
|---|---|---|---|
| 컨트롤러 파라미터 — 목록 필터 | 8 | `Converter` → 400 | **안 한다.** 없는 분야로 거르면 빈 목록이 나오는 것이 자연스럽다 |
| 컨트롤러 파라미터 — 관리자 분야 설정(`/{domain}`·미리보기) | 3 | `Converter` → 400 | 서비스 → 404(`DOMAIN_001`, 이미 있음) |
| 요청 DTO(문제·문서·주제·생성 요청) | 5 | `@JsonCreator` → 400 | **서비스에서 반드시 한다** → 400 |
| 배치 설정 파일 | 1 | 줄 단위 — 틀린 줄만 버린다(지금 규칙) | 파일이 곧 등록부라 검사 대상이 아니다 |
| 배치 수동 실행 `--domain=` | 1 | 형식 오류면 실패 | 4.4절의 "전체"(파일 → yml → 기본 11개 순)에 없으면 실패 — 돈이 드는 실행을 모르는 분야로 돌리지 않는다 |

**요청 DTO 5개의 존재 검사는 빠뜨리면 안 된다.** 없는 분야로 문제를 저장하면 외래키 위반이 나는데,
`GlobalExceptionHandler`가 그 예외를 따로 처리하지 않아 **500**이 된다(지난 작업 Minor 4에서
같은 포괄 처리기를 확인했다). 쓰기 전에 `catalog.exists(code)`로 확인해 400으로 돌려준다.

## 8. 기동 — enum을 따라가던 동기화가 "빈 표 채우기"로 바뀐다

지금 `DomainSettingSyncRunner`는 enum을 기준으로 없는 행을 만들고 남는 행을 지운다.
enum이 없어지면 **기준이 사라진다.** 그래서 역할을 줄인다.

| 지금 | 바뀐 뒤 |
|---|---|
| enum에 있고 표에 없으면 만든다 | **표가 완전히 비어 있을 때만** 기본 11개를 채운다 |
| 표에 있고 enum에 없으면 지운다 | 하지 않는다 — 지우는 것은 사람이 화면에서만 한다 |

기본 11개와 내장 힌트 4개는 `DefaultDomains`(`llm.support`) 한 곳에 둔다. 지금 `Domain` enum과
`DomainHints.BUILT_IN`에 흩어져 있는 값을 합친 것이다. **본코드에서 특정 분야 코드를 아는 곳은
이 클래스 하나뿐이어야 한다** — 구현 계획의 마지막에 "본코드에 코드 문자열 상수가 이 파일 밖에
없다"를 확인한다.

기존 DB에는 이미 11행이 있으므로 이 러너는 아무것도 하지 않는다. 새로 까는 DB(CI 포함)에서만 돈다.

## 9. 화면

지난 개편(한 줄 목록 + 오른쪽 미리보기) 위에 둘을 더한다.

- **목록 위 "분야 추가"** — 코드·이름 두 칸과 추가 버튼. 힌트는 추가한 뒤 그 줄의 "편집"에서 쓴다
  (추가 폼을 한 줄로 유지하려고). 추가된 줄은 꺼진 채로 맨 끝에 나타나고, 그 줄의 편집칸이
  자동으로 펼쳐져 힌트를 바로 쓰게 한다.
- **편집칸 안의 "삭제"** — 줄에 늘 떠 있지 않고 편집을 펼쳐야 보인다. 자주 쓰지 않고 되돌릴 수
  없는 동작이라 한 번 더 들어가야 닿게 둔다. 누르면 확인을 묻고, 거부되면 5절의 메시지를 그대로 보인다.

사용자 화면(문제 목록·퀴즈·복습 등)은 이미 `GET /api/domains`에서 목록을 받으므로 고칠 것이 없다.
새 분야는 문제가 생기는 순간 필터에 나타난다.

## 11. 규모와 순서

본코드 69개, 테스트 52개 파일이 바뀐다. 대부분 `Domain` → `DomainCode` 치환이다.
진짜 설계가 필요한 곳은 셋이다: 카탈로그(4.3), 추가·삭제(5절·9절), V20(4.2).

구현 순서의 원칙 — **매 단계가 초록으로 끝나야 한다.** 69개 파일을 한 번에 바꾸면 중간에
컴파일이 안 되는 커밋이 생긴다. 그래서 `DomainCode`를 먼저 만들고 enum과 **잠시 함께 두어**
바깥쪽부터 차례로 옮긴 뒤 마지막에 enum을 지운다. 구체적인 단계는 구현 계획에서 정한다.

테스트의 `Domain.NETWORK` 같은 고정값은 테스트 전용 상수 모음(`TestDomains`)으로 옮긴다.
본코드에 같은 상수를 두지 않는 이유는 8절 — 본코드는 특정 분야를 몰라야 한다.

## 12. 남겨 둔 결정

- **삭제 경쟁 조건의 500(5절).** 관리자 한 명이라 받아들였다. 여러 명이 쓰게 되면 외래키 위반을
  409로 바꾸는 처리기를 붙인다.
- **거절된 초안 때문에 못 지우는 분야.** 실수로 만든 분야에 생성을 한 번 돌려 거절만 남겨도 못
  지운다. 실제로 겪으면 "거절된 초안은 세지 않고 함께 지운다"로 바꿀 수 있다 — 대신 그만큼의
  거절 사례가 모델 되먹임에서 사라진다.
- **`docs/02-domain-enums.md`.** 분야는 더 이상 enum이 아니다. 난이도·문제 유형은 여전히 enum이므로
  문서를 지우지 않고 분야 절만 "등록부"로 고쳐 쓴다.
