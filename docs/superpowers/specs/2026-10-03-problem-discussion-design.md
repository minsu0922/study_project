# 문제별 토론 — 커뮤니티 1단계 설계

작성일: 2026-10-03
선행 작업: 없음. 학습자가 글을 남기는 기존 통로는 문제 제보(V17)뿐이고 그 글은 관리자만 본다.

문제마다 토론방을 하나 두고 학습자가 해설 아래에서 댓글과 답글로 이야기할 수 있게 한다.
공개 서비스로 열 계획이라 불특정 다수가 쓰는 것을 전제로 신고와 관리자 가림까지 함께 만든다.

---

## 1. 무엇을 하고, 무엇을 하지 않나

커뮤니티는 네 단계로 나눠 만든다. 이 문서는 1단계만 다룬다.

| 단계 | 내용 | 이 문서 |
|---|---|---|
| 1 | 문제별 토론 + 최소 운영 장치 | 다룬다 |
| 2 | 알림 (내 글에 답글이 달리면 알려 줌) | 다루지 않는다 |
| 3 | 일반 게시판 (문제와 무관한 글, 분야별 분류) | 다루지 않는다 |
| 4 | 프로필·활동 내역 | 닉네임만 당겨 온다 |

| 한다 | 하지 않는다 |
|---|---|
| 댓글·답글 작성, 수정, 삭제 | 추천(좋아요) — 구조만 열어 두고 뒤 단계에서 더한다 |
| 닉네임 설정·변경 | 프로필 화면, 내가 쓴 글 모아 보기 |
| 신고, 관리자 가림·복구·기각 | 신고 누적 자동 가림, 금칙어 필터 |
| 댓글 작성 도배 방지(분당 5건) | 사용자 차단·정지 |
| 평문 본문 1,000자 | 마크다운, 이미지 첨부, 멘션 |

**사용자 결정(2026-10-03).**

| 결정 | 고른 것 | 버린 것 |
|---|---|---|
| 커뮤니티의 첫 형태 | 문제별 토론 | 질문 게시판, 학습 기록 공유 |
| 대상 사용자 | 불특정 다수(공개 예정) | 나 혼자, 지인 몇 명 |
| 읽기 | 누구나. 비로그인 방문자 포함 | 푼 사람만, 로그인 사용자만 |
| 쓰기 | 그 문제를 푼 로그인 사용자만 | 로그인 사용자 누구나 |
| 글쓴이 표시 | 닉네임 | 로그인 아이디, 익명 번호 |
| 신고 처리 | 관리자만 가린다 | 신고 3건 자동 가림, 금칙어 |
| 추천 | 지금은 없음, 시간순 | 추천순 기본 |
| 댓글을 묶는 구조 | 토론방 표를 사이에 둔다 | 댓글에 대상 종류·번호를 적기, 문제 전용 댓글 표 |

**공개 전에 따로 다뤄야 할 것.** 사용자 차단·정지가 없다. 같은 사람이 문제 글을 계속 올리면
관리자가 글마다 가려야 한다. 1단계 범위에서는 뺐지만 서비스를 열기 전에 설계해야 한다.

## 2. 데이터 구조

마이그레이션은 `V21__problem_discussion.sql` 한 파일이다.

### 2.1 표

| 표 | 주요 칸 | 역할 |
|---|---|---|
| `discussion` (신규) | `id`, `problem_id`, `created_at` | 토론방. 문제 하나에 방 하나 |
| `comment` (신규) | `id`, `discussion_id`, `user_id`, `parent_id`, `body`, `status`, `created_at`, `edited_at` | 댓글과 답글 |
| `comment_report` (신규) | `id`, `comment_id`, `user_id`, `reason`, `detail`, `status`, `admin_note`, `created_at`, `resolved_at` | 신고 |
| `user` (변경) | `nickname` 추가 | 글쓴이 표시 이름 |

### 2.2 토론방을 사이에 두는 이유

댓글은 문제를 직접 가리키지 않고 방을 가리킨다. 읽는 순서는 "문제 812 → 방 15 → 방 15의 댓글들"이다.

```
discussion
 id | problem_id
 15 | 812
 16 | 640

comment
 id  | discussion_id | user_id | parent_id | body                               | status
 201 |      15       |    7    |   NULL    | 서명이 있는데 왜 내용을 읽을 수 있나요? | VISIBLE
 202 |      15       |    9    |    201    | 서명은 위조만 막고 암호화는 안 합니다   | VISIBLE
 203 |      15       |    7    |    201    | 이해됐어요 감사합니다                  | VISIBLE
 204 |      16       |    9    |   NULL    | 해설의 예시가 헷갈려요                 | VISIBLE
```

3단계에서 게시판이 생기면 `discussion`에 `post_id` 칸을 더해 "게시글마다 방 하나"를 만든다.
`comment`와 `comment_report`는 방만 알면 되므로 그때 손대지 않는다. 신고·가림·도배 방지 코드도 그대로 쓴다.

버린 두 안은 이렇다. 댓글에 `target_type`과 `target_id`를 적는 안은 외래키를 걸 수 없어
문제가 지워져도 댓글이 남는다. 문제 전용 댓글 표는 게시판 때 운영 장치를 한 벌 더 써야 한다.

### 2.3 규칙

| 대상 | 규칙 |
|---|---|
| `discussion.problem_id` | 유일 제약, NULL 허용. NULL은 3단계의 게시글 방을 위한 자리다 |
| 방을 만드는 때 | 그 문제에 첫 댓글이 달릴 때. 문제 수만큼 빈 방을 미리 만들지 않는다 |
| `comment.parent_id` | NULL이면 댓글, 값이 있으면 답글. 답글은 한 단계까지만 받는다 |
| 답글의 답글 | 받는 쪽이 원글의 `id`로 바꿔 저장한다. 같은 묶음 아래에 이어 붙는다 |
| `comment.status` | `VISIBLE`, `HIDDEN`(관리자가 가림), `DELETED`(본인 삭제) |
| 삭제 | 행을 지우지 않고 상태만 바꾼다. 답글이 달린 글은 "삭제된 댓글입니다"로 자리가 남는다 |
| `comment.body` | 평문 1,000자까지. 화면에 낼 때 이스케이프한다 |
| `comment.user_id` | NULL 허용. 탈퇴하면 NULL이 되고 글쓴이는 "탈퇴한 사용자"로 표시한다 |
| `comment_report` | `(comment_id, user_id)` 유일 제약. 한 사람이 같은 글을 한 번만 신고한다 |
| `comment_report.status` | `PENDING`, `ACCEPTED`(가림), `DISMISSED`(기각). 문제 제보(V17)와 같은 세 값이다 |
| `user.nickname` | 유일 제약, NULL 허용, 2~12자. 첫 댓글을 쓸 때 정하고 나중에 바꿀 수 있다 |

### 2.4 외래키와 인덱스

| 외래키 | 지워질 때 | 이유 |
|---|---|---|
| `discussion.problem_id → problem.id` | CASCADE | 문제가 사라지면 토론이 가리킬 대상이 없다. 문제 제보(V17)와 같은 판단이다 |
| `comment.discussion_id → discussion.id` | CASCADE | 방이 사라지면 댓글도 함께 지운다 |
| `comment.user_id → user.id` | SET NULL | 탈퇴해도 토론의 흐름은 남긴다 |
| `comment.parent_id → comment.id` | CASCADE | 원글 행이 지워지는 것은 방이 지워질 때뿐이다 |
| `comment_report.comment_id → comment.id` | CASCADE | 신고는 그 글에 딸린 것이다 |
| `comment_report.user_id → user.id` | CASCADE | 문제 제보(V17)와 같다 |

| 인덱스 | 받치는 조회 |
|---|---|
| `comment (discussion_id, parent_id, created_at)` | 한 방의 댓글을 시간순으로 쪽 나눠 읽기 |
| `comment_report (status, created_at)` | 신고함의 처리 안 된 건을 시간순으로 읽기 |

### 2.5 "풀었는지" 판정

표를 따로 만들지 않는다. 기존 `submission`에 그 사용자와 그 문제의 제출이 한 건이라도 있으면 푼 것이다.
맞혔는지는 보지 않는다. 틀린 사람이 묻고 싶은 것이 가장 많다.

## 3. API와 권한

응답은 기존 봉투(`{success, data, error}`)를 그대로 쓴다.

| API | 누가 | 동작 |
|---|---|---|
| `GET /api/quiz/{problemId}/comments` | 누구나(비로그인 포함) | 댓글 목록. 20개씩 쪽 나누기 |
| `GET /api/quiz/comment-counts?problemIds=1,2` | 누구나 | 문제별 댓글 수. 문제 목록이 쓴다 |
| `POST /api/me/comments` | 그 문제를 푼 로그인 사용자 | 댓글 작성. 본문에 `problemId`를 싣는다. `parentId`가 있으면 답글 |
| `PUT /api/me/comments/{id}` | 글쓴이 본인 | 수정. `edited_at`을 찍는다 |
| `DELETE /api/me/comments/{id}` | 글쓴이 본인 | 삭제. 상태만 `DELETED`로 바꾼다 |
| `POST /api/me/comment-reports` | 로그인 사용자 | 신고. 본문에 `commentId`를 싣는다 |
| `GET /api/me/nickname` | 로그인 사용자 | 지금 닉네임 |
| `PUT /api/me/nickname` | 로그인 사용자 | 닉네임 설정·변경 |
| `GET /api/admin/comment-reports` | 관리자 | 신고 목록 |
| `GET /api/admin/comment-reports/pending-count` | 관리자 | 처리 안 된 신고 수 |
| `POST /api/admin/comments/{id}/hide` | 관리자 | 가림. 그 글의 `PENDING` 신고를 모두 `ACCEPTED`로 바꾼다 |
| `POST /api/admin/comments/{id}/restore` | 관리자 | 복구 |
| `POST /api/admin/comment-reports/{id}/dismiss` | 관리자 | 신고 기각 |

경로는 이 저장소의 규칙을 따른다(2026-10-04 구현 계획을 쓰며 고쳤다). 문제 읽기는 `/api/quiz/**`가
이미 공개 경로이고, 로그인한 사람이 자기 것을 다루는 API는 전부 `/api/me/**`에 있다. 그 두 자리에
두면 `SecurityConfig`에 규칙을 더하지 않아도 권한이 맞게 걸린다.

### 3.1 목록 응답

```json
{
  "solved": true,
  "canWrite": true,
  "total": 3,
  "hasNext": false,
  "comments": [
    {
      "id": 201,
      "nickname": "민수",
      "body": "서명이 있는데 왜 내용을 읽을 수 있나요?",
      "status": "VISIBLE",
      "mine": true,
      "edited": false,
      "createdAt": "2026-10-03T10:12:00",
      "replies": [
        { "id": 202, "nickname": "지은", "body": "서명은 위조만 막고 암호화는 안 합니다",
          "status": "VISIBLE", "mine": false, "edited": false, "createdAt": "2026-10-03T10:20:00" }
      ]
    }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `solved` | 요청한 사람이 이 문제를 풀었는지. 비로그인이면 `false`다. 화면이 접을지와 쓰기 칸을 낼지를 이 값으로 정한다 |
| `canWrite` | 쓸 수 있는지. 풀었거나 관리자면 `true`다 |
| `total` | 가려지거나 삭제된 글을 뺀 댓글·답글 수. 문제 목록의 댓글 수와 같은 값이다 |
| `hasNext` | 다음 쪽이 있는지. "더 보기"를 낼지 정한다 |
| `mine` | 내가 쓴 글인지. 수정·삭제 버튼을 낼지 정한다 |
| `replies` | 그 댓글의 답글 전부. 쪽 나누기는 댓글 단위로만 한다 |

`HIDDEN`과 `DELETED`인 글은 `body`와 `nickname`을 비워 보낸다. 화면에서만 가리면 응답을 열어 읽을 수 있다.
답글이 없는 `DELETED` 댓글은 목록에서 뺀다.

### 3.2 권한 규칙

| 규칙 | 이유 |
|---|---|
| 읽기는 서버가 막지 않는다 | 안 푼 사람에게 접어 두는 것은 화면의 일이다. 서버는 `solved`만 알려 준다 |
| 쓰기는 서버가 요청마다 "풀었는지"를 확인한다 | 화면에서만 막으면 주소를 직접 불러 쓸 수 있다 |
| 닉네임이 없으면 쓰기를 거절한다 | 화면이 그 응답을 받아 닉네임 입력을 먼저 띄운다 |
| 관리자는 풀지 않아도 쓸 수 있다 | 신고된 글 아래에 안내 답글을 달 일이 있다 |
| 신고는 풀지 않아도 할 수 있다 | 읽을 수 있으면 신고도 할 수 있어야 한다 |

### 3.3 도배 방지

기존 요청 제한(Redis 토큰 버킷)에 댓글 작성용 설정을 하나 더한다.

```yaml
ratelimit:
  comment:                       # 댓글·답글 작성 — 사용자당
    capacity: 5
    refill-tokens: 5
    refill-period-seconds: 60    # = 분당 5회
```

읽기 API는 공개지만 기존 `api` 제한(IP당 분당 60회)이 그대로 걸린다.

## 4. 화면

| 화면 | 바뀌는 것 |
|---|---|
| 퀴즈 플레이어(자유 퀴즈·데일리·복습) | 풀기 전에는 문제 아래에 접힌 토론 입구가 있다. 답을 제출하면 그 자리에 토론이 펼쳐진다 |
| 문제 목록(`problems.html`) | 문제마다 댓글 수를 보여 준다. 줄을 누르면 지금처럼 플레이어로 가고, 토론은 거기서 본다 |
| 오답노트(`wrong-answers.html`) | 카드마다 "토론 N개 보기" 입구가 있다. 누르면 펼쳐진다. 카드 20장이 각자 목록을 읽으면 몇 쪽만 넘겨도 요청 제한(분당 60회)에 걸려서 접어 둔다(2026-10-04 최종 검토에서 고쳤다) |
| 마이페이지(`mypage.html`) | 닉네임 변경 칸. 계정 설정(비밀번호·탈퇴)이 있는 화면이다 |
| 관리 콘솔(신규 `admin/comments.html`) | 신고 목록, 신고된 글 보기, 가림·복구·기각 |

| 규칙 | 내용 |
|---|---|
| 공용 스크립트 | 토론 영역은 `js/discussion.js` 한 파일이 그린다. 세 화면이 같이 쓴다 |
| 안 푼 문제 | 토론을 접어 두고 "정답 이야기가 있을 수 있습니다"를 보여 준다. 누르면 펼친다. 쓰기 칸 자리에는 "문제를 풀면 참여할 수 있습니다"를 낸다 |
| 정렬과 쪽 나누기 | 시간순, 20개씩 "더 보기" |
| 닉네임 없는 사용자 | 쓰기를 누르면 그 자리에서 닉네임 입력을 받고 이어서 등록한다 |
| 비로그인 방문자 | 쓰기를 누르면 로그인 화면으로 보낸다 |
| 가려지거나 삭제된 글 | "관리자가 가린 댓글입니다", "삭제된 댓글입니다"로 자리만 보여 준다 |
| 관리 콘솔 메뉴 | "신고" 옆에 처리 안 된 건수를 띄운다. 문제 제보 건수와 같은 방식이다 |

## 5. 오류 처리

| 상황 | 응답 |
|---|---|
| 안 푼 문제에 쓰기 | 403, "문제를 풀면 참여할 수 있습니다" |
| 닉네임 없이 쓰기 | 409, 화면이 닉네임 입력을 띄운다 |
| 닉네임 중복 | 409, "이미 쓰는 이름입니다" |
| 남의 글 수정·삭제 | 403 |
| 가려지거나 삭제된 글에 답글·수정 | 409 |
| 같은 글 두 번 신고 | 409. DB 유일 제약이 막는다 |
| 분당 5건 초과 작성 | 429. 기존 요청 제한과 같은 응답이다 |
| 없는 문제·없는 댓글 | 404 |

오류 코드는 `ErrorCode`에 `DISCUSSION_` 머리로 더한다.

**첫 댓글 둘이 동시에 올 때.** 두 요청이 모두 방이 없다고 보고 방을 만들려 하면 하나가
`discussion.problem_id` 유일 제약에 걸린다. 걸린 쪽은 방을 다시 조회해 그 방에 댓글을 단다.
사용자에게 오류를 돌려주지 않는다.

## 6. 테스트

| 종류 | 확인하는 것 |
|---|---|
| 권한 | 안 푼 사용자의 쓰기 거절, 비로그인 읽기 허용, 남의 글 수정·삭제 거절, 관리자의 쓰기 허용 |
| 상태 | 답글 달린 글을 지우면 자리가 남는지, 답글 없는 글을 지우면 목록에서 빠지는지 |
| 응답 | 가려진 글의 본문과 닉네임이 응답에 실리지 않는지, `total`이 가려진 글을 빼는지 |
| 답글 | 답글의 답글이 원글 아래로 붙는지 |
| 동시성 | 한 문제에 첫 댓글 둘이 동시에 올 때 방이 하나만 생기고 댓글은 둘 다 저장되는지 |
| 신고 | 같은 글을 두 번 신고하면 거절되는지, 가리면 그 글의 `PENDING` 신고가 모두 `ACCEPTED`가 되는지 |
| 닉네임 | 중복 거절, 길이 제한, 닉네임 없는 사용자의 쓰기 거절 |
| 도배 방지 | 분당 6번째 작성이 429인지 |
| 화면 | 닉네임 없는 사용자의 첫 댓글 흐름, 안 푼 문제에서 접힘, 관리자 가림 뒤 표시 |

화면은 앱을 띄워 브라우저로 확인한다(`.claude/skills/verify`).
